1. Native CSS Nesting

For years, CSS developers relied on preprocessors like Sass and Less for one killer feature: nesting. Writing selectors inside other selectors mirrors the HTML structure and dramatically reduces repetition. Now, native CSS supports nesting directly in the browser — no build step required. The & symbol represents the parent selector, and you can nest rules inside any rule block.

Nesting isn't just syntactic sugar. It groups related styles together, making it immediately clear which styles belong to which component. When you revisit code months later, nested CSS reads like a self-contained component definition rather than a scattered collection of flat selectors that you have to mentally piece together.

The & nesting selector refers to the nearest enclosing style rule's selector. In most cases, you place & at the beginning of a nested selector to indicate "this parent, then this child." However, you can also place & elsewhere in the selector to create more complex relationships, such as .dark & to style the component differently when it's inside a dark-themed container.

Why Native Nesting Matters: Preprocessor nesting requires a build tool, adds a compilation step, and produces flat CSS anyway. Native nesting works directly in the browser, is debuggable in DevTools with the actual nested structure, and reduces the cognitive gap between what you write and what runs.

Flat CSS vs Nested CSS

Compare these two approaches. They produce the same result, but the nested version is shorter and easier to scan:

2. Nesting Rules

Understanding when and how to use & is the key to mastering CSS nesting. The ampersand works differently depending on where you place it, and in some cases it's optional. Let's break down every pattern you'll encounter.

Pseudo-classes use &:hover, &:focus, &:active, etc. The & directly attaches the pseudo-class to the parent selector with no space, producing selectors like .btn:hover. This is the most common nesting pattern and makes interactive states easy to co-locate with their base styles.

Pseudo-elements work the same way: &::before, &::after, &::placeholder. They attach directly to the parent, producing .input::placeholder and similar selectors.

Child/descendant selectors use & .child with a space. The space between & and the child selector is critical — it produces a descendant combinator. You can also use & > .child for direct children.

When & is optional: If a nested selector starts with a symbol that can't begin a valid selector on its own (like :, ::, +, ~, >), the browser implicitly prepends &. So :hover { ... } inside a rule block is equivalent to &:hover { ... }. However, explicitly writing & is recommended for clarity.

.btn {
  padding: 0.5rem 1rem;
  background: #6366f1;
  color: #fff;
  border: 2px solid transparent;
  border-radius: 6px;
  cursor: pointer;
  position: relative;

  /* Pseudo-classes: & attaches directly */
  &:hover {
    background: #4f46e5;
  }

  &:focus-visible {
    outline: 2px solid #6366f1;
    outline-offset: 2px;
  }

  &:active {
    transform: scale(0.98);
  }

  &:disabled {
    opacity: 0.5;
    cursor: not-allowed;
  }

  /* Pseudo-elements: & attaches directly */
  &::after {
    content: "";
    position: absolute;
    inset: -4px;
    border-radius: 10px;
    border: 2px solid transparent;
    transition: border-color 0.2s;
  }

  /* Child selectors: space between & and child */
  & .btn-icon {
    margin-right: 0.5rem;
  }

  /* Direct child combinator */
  & > span {
    font-weight: 600;
  }

  /* Reverse nesting: style when inside another context */
  .dark & {
    background: #818cf8;
  }
}

3. Nesting Media Queries

One of the most powerful applications of CSS nesting is placing @media queries directly inside rule blocks. Instead of scattering your responsive styles across separate media query blocks at the bottom of your file, you can co-locate them with the component they modify. This is a massive improvement for maintainability — when you look at a component's styles, you see everything about it, including how it responds to different screen sizes.

When you nest a @media query inside a rule, the browser automatically scopes it to that selector. You don't need to repeat the selector inside the media block. The result is identical to writing the media query separately with the full selector, but your source code is far more organized.

This pattern works with all at-rules that can be nested: @media, @container, @supports, and @layer. You can even nest media queries inside each other for compound conditions.

Why Co-Located Media Queries Win: In traditional CSS, a component's responsive behavior is defined far away from its base styles, often hundreds of lines apart. When you modify a component, you must hunt for all its media queries. With nesting, every responsive rule lives right next to the styles it modifies. One component, one location, all breakpoints. 
/* Traditional: component styles scattered across the file */
.pricing-card {
  padding: 1rem;
  display: grid;
  gap: 1rem;
}

/* ... 200 lines later ... */

@media (min-width: 768px) {
  .pricing-card {
    padding: 2rem;
    grid-template-columns: 1fr 1fr;
  }
}

/* ... 100 more lines ... */

@media (min-width: 1024px) {
  .pricing-card {
    padding: 3rem;
    grid-template-columns: 1fr 1fr 1fr;
  }
}

/* ---- Nested: everything in one place ---- */
.pricing-card {
  padding: 1rem;
  display: grid;
  gap: 1rem;

  @media (min-width: 768px) {
    padding: 2rem;
    grid-template-columns: 1fr 1fr;
  }

  @media (min-width: 1024px) {
    padding: 3rem;
    grid-template-columns: 1fr 1fr 1fr;
  }
}

4. The :has() Selector

The :has() selector is arguably the most significant addition to CSS selectors in a decade. It's often called "the parent selector" because it allows you to select an element based on its children or descendants. Before :has(), this was impossible in CSS — you could only select children based on parents, never the reverse. This limitation forced developers to use JavaScript for countless styling patterns that should have been pure CSS.

The syntax is straightforward: A:has(B) selects element A if it contains element B as a descendant. For example, .card:has(img) selects cards that contain an image, form:has(input:invalid) selects forms that contain an invalid input, and li:has(+ li) selects list items that are followed by another list item (using the adjacent sibling combinator inside :has()).

The power of :has() goes far beyond simple parent selection. It can check for any relational selector: siblings, specific child combinations, states of descendants, and more. Combined with :valid, :checked, :empty, and other state pseudo-classes, it enables complex UI logic without a single line of JavaScript.

Why :has() Changes Everything: Before :has(), showing a "form is valid" indicator required JavaScript to check all inputs and toggle a class. Now, form:has(input:invalid) does it in pure CSS. Interactive UIs that previously needed JS event listeners can now be declarative CSS rules. 
/* Select a card that contains an image */
.card:has(img) {
  grid-template-rows: 200px 1fr;
}

/* Select a card that does NOT contain an image */
.card:not(:has(img)) {
  grid-template-rows: 1fr;
}

/* Style a form label when its sibling input is valid */
.field:has(input:valid) {
  & label {
    color: #10b981;
  }
  & .field-indicator {
    opacity: 1;
  }
}

/* Style a form label when its sibling input is invalid and touched */
.field:has(input:invalid:not(:placeholder-shown)) {
  & label {
    color: #ef4444;
  }
}

5. :is() and :where()

The :is() and :where() pseudo-class functions let you group selectors to reduce repetition. Instead of writing the same declarations for multiple selectors, you can combine them into a single rule. They both accept a comma-separated list of selectors as their argument, and the rule matches if any of the listed selectors match.

The critical difference is specificity. :is() takes on the specificity of its most specific argument. If you write :is(.card, #hero, div), the specificity of the entire :is() expression is that of #hero (1-0-0). :where(), on the other hand, always contributes zero specificity, no matter what selectors you put inside it. This makes :where() perfect for creating easily overridable base styles.

Both functions are also "forgiving" — if one selector in the list is invalid, the others still work. In a normal selector list, one invalid selector invalidates the entire rule. This forgiving behavior is useful when using selectors that might not be supported in all browsers.

Practical Guideline: Use :is() when you want the grouped selectors to carry their natural specificity. Use :where() when you're writing defaults or base styles that should be easy to override without specificity battles. 
/* :is() - groups selectors, takes highest specificity */
:is(h1, h2, h3, h4) {
  line-height: 1.2;
  color: #1e293b;
}

/* Without :is(), you'd write: */
h1, h2, h3, h4 {
  line-height: 1.2;
  color: #1e293b;
}

/* :is() shines in complex selectors */
:is(article, section, aside) :is(h2, h3) {
  margin-top: 1.5em;
}

/* Without :is(), this would be 6 selectors:
   article h2, article h3, section h2,
   section h3, aside h2, aside h3 */

/* :where() - same grouping, but ZERO specificity */
:where(article, section, aside) :where(h2, h3) {
  margin-top: 1.5em;
  /* Specificity: 0-0-0 — trivially overridable! */
}

/* Easy override with just an element selector */
section h2 {
  margin-top: 0; /* Wins because 0-0-2 > 0-0-0 */
}

6. :not() Advanced

The :not() pseudo-class has been around for a while, but its modern form is far more powerful. Originally, :not() could only accept a single simple selector. Now it accepts a full selector list, just like :is(). You can write :not(.active, .disabled) to exclude multiple classes, or :not(:first-child, :last-child) to target only middle elements.

The specificity of :not() follows the same rule as :is(): it takes on the specificity of its most specific argument. :not() itself doesn't add any specificity — it's the argument that counts. So :not(.foo) has specificity 0-1-0 (from .foo), and :not(#bar) has specificity 1-0-0.

Complex negation patterns become possible by combining :not() with other pseudo-classes. For example, :not(:has(img)) selects elements that don't contain an image, :not(:first-child):not(:last-child) selects only middle children, and input:not(:placeholder-shown):not(:focus) targets inputs that have content but aren't currently focused.

/* Exclude multiple states at once */
.nav-link:not(.active, .disabled) {
  opacity: 0.7;
}

/* Style all list items except first and last */
li:not(:first-child, :last-child) {
  border-top: 1px solid #e2e8f0;
  border-bottom: 1px solid #e2e8f0;
}

/* Target inputs that have content but aren't focused */
input:not(:placeholder-shown):not(:focus) {
  border-color: #10b981;
}

/* Select cards that don't have images */
.card:not(:has(img)) {
  min-height: 200px;
}

7. Combining :has() with Nesting

When you combine :has() with native CSS nesting, you unlock remarkably expressive component patterns — all without JavaScript. The nesting keeps the code organized and readable, while :has() provides the conditional logic. Together, they let you build interactive, state-aware components in pure CSS.

Consider a toggle switch: when the hidden checkbox inside it is :checked, the entire toggle's appearance changes. Or an accordion: when a <details> element is open, the parent section adjusts its styling. These patterns replace what previously required JavaScript event listeners and class toggling.

The key insight is that :has() + nesting turns CSS into a declarative state machine. You define how a component looks in each state (has checked input, has focused child, has valid form fields) and CSS handles the transitions between states automatically.

/* Interactive toggle - zero JavaScript */
.toggle {
  display: flex;
  align-items: center;
  gap: 0.75rem;
  cursor: pointer;

  & .toggle-track {
    width: 48px;
    height: 26px;
    background: #cbd5e1;
    border-radius: 13px;
    position: relative;
    transition: background 0.2s;

    &::after {
      content: "";
      width: 22px;
      height: 22px;
      background: #fff;
      border-radius: 50%;
      position: absolute;
      top: 2px;
      left: 2px;
      transition: transform 0.2s;
    }
  }

  /* When the hidden input is checked, restyle everything */
  &:has(input:checked) {
    & .toggle-track {
      background: #6366f1;

      &::after {
        transform: translateX(22px);
      }
    }

    & .toggle-label {
      color: #6366f1;
      font-weight: 600;
    }
  }
}

Challenge: Pure CSS Interactive Form

Build a registration form where all interactive behavior is powered by :has() and CSS nesting — zero JavaScript allowed. The form should include the following behaviors:

Requirements:

  1. Floating labels: Labels start inside the input and float above when the input has content (use :not(:placeholder-shown) combined with :has()).
  2. Validation feedback: Each field shows a green check mark when valid and a red error message when invalid (after the user has started typing). Use :has(input:valid) and :has(input:invalid:not(:placeholder-shown)).
  3. Submit button state: The submit button is visually disabled (grayed out, not clickable) until all fields are valid. Use form:has(input:invalid) .submit-btn to conditionally style the button.
  4. Progress indicator: Show a progress bar or step indicator that fills as more fields become valid.
  5. All styles must use CSS nesting for organization. No flat selectors outside of the main component block.

Starter HTML:

<form class="smart-form">
  <div class="smart-field">
    <input type="text" id="sf-name" placeholder=" " required minlength="2">
    <label for="sf-name">Full Name</label>
    <span class="smart-field-check">&#10003;</span>
    <span class="smart-field-error">Required (min 2 chars)</span>
  </div>
  <!-- Add more fields: email, password, confirm password -->
  <button type="submit" class="smart-submit">Create Account</button>
</form>

Key CSS Patterns:

.smart-form {
  /* Nest everything here */

  & .smart-field {
    position: relative;

    & label {
      /* Position inside input by default */
      position: absolute;
      top: 50%;
      transform: translateY(-50%);
      transition: all 0.2s;
    }

    /* Float label when input has content */
    &:has(input:not(:placeholder-shown)) label,
    &:has(input:focus) label {
      top: 0;
      font-size: 0.75rem;
      transform: translateY(-100%);
    }

    /* Valid state */
    &:has(input:valid:not(:placeholder-shown)) {
      & .smart-field-check { opacity: 1; }
      & label { color: #10b981; }
    }

    /* Invalid state after interaction */
    &:has(input:invalid:not(:placeholder-shown)) {
      & .smart-field-error { display: block; }
      & label { color: #ef4444; }
    }
  }

  /* Submit button disabled when form has invalid inputs */
  &:has(input:invalid) .smart-submit {
    opacity: 0.5;
    pointer-events: none;
  }
}
