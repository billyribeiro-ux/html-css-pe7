Understanding Space

Master the box model, display types, positioning, and stacking to control how elements occupy and share space.

1. The Box Model

Every element in CSS is a rectangular box. The box model describes how the size of that box is calculated using four layers: content, padding, border, and margin. Understanding this model is essential because it determines how much space every element occupies on the page and how elements relate to each other spatially.

The content area holds the actual text, images, or child elements. Padding is the space between the content and the border — it is inside the element and takes on the element's background color. Border wraps around the padding and content. Margin is the space outside the border that separates the element from its neighbors. Margins are transparent and can collapse (adjacent vertical margins merge into the larger of the two).

By default, CSS uses content-box sizing: when you set width: 300px, that is the width of the content only. Padding and border are added on top, making the total rendered width larger. This often catches beginners off guard. The border-box model changes this: width: 300px includes padding and border, so the content shrinks to fit. Most modern CSS resets apply box-sizing: border-box to all elements.

The difference between the two models becomes critical when building layouts. With content-box, adding padding to a 50% width element pushes it past 50% of its container, breaking side-by-side layouts. With border-box, padding is absorbed into the width, making percentage-based layouts predictable and reliable.

Why Use border-box?

The border-box model makes CSS math intuitive. When you say an element is width: 50%, it is exactly 50% of its parent — padding and border included. This is why nearly every CSS framework and reset stylesheet includes *, *::before, *::after { box-sizing: border-box; }. It prevents countless layout bugs and makes responsive design far simpler.

Box Model Code

/* Apply border-box globally (recommended) */
*, *::before, *::after {
  box-sizing: border-box;
}

/* Box model properties */
.card {
  width: 300px;           /* content width (or total with border-box) */
  padding: 20px;          /* inner spacing */
  border: 2px solid #ccc; /* visible border */
  margin: 16px;           /* outer spacing */
}

/* Margin shorthand: top right bottom left */
.element {
  margin: 10px 20px 10px 20px;
  /* Or: margin: 10px 20px; (vertical | horizontal) */
  /* Or: margin: 10px; (all sides) */
}

2. Display Types

The display property is one of the most important in CSS. It determines how an element participates in the document flow — whether it takes up a full row, sits beside other elements, or is removed from the flow entirely. The three foundational display values are block, inline, and inline-block.

Block elements take up the full width available and start on a new line. They stack vertically. You can set width, height, margin, and padding on all sides. Examples include <div>, <p>, <h1>, and <section>. Block is the default display for most structural elements.

Inline elements flow within text, taking up only as much width as their content. They sit side by side on the same line. You cannot set width or height on inline elements, and vertical margins have no effect. Horizontal padding and margins work but do not push other lines away vertically. Examples include <span>, <a>, <strong>, and <em>.

Inline-block is the hybrid: elements flow inline (sitting next to each other) but accept width, height, and vertical margins like block elements. This is useful for things like navigation links that need a set size and padding but should sit side by side.

Display Types

/* Block: full width, stacks vertically */
.container { display: block; }

/* Inline: flows with text, no width/height */
.tag { display: inline; }

/* Inline-block: flows inline, but accepts dimensions */
.nav-link {
  display: inline-block;
  width: 120px;
  padding: 8px 16px;
}

/* None: completely removed from layout */
.hidden { display: none; }

3. Positioning

CSS positioning lets you take elements out of the normal document flow and place them precisely where you want. There are five positioning modes, each with different behavior. Understanding when to use each one is key to building complex layouts, overlays, tooltips, sticky headers, and more.

Static is the default. Elements appear in the normal document flow in the order they appear in the HTML. The top, right, bottom, left, and z-index properties have no effect on statically positioned elements.

Relative positioning keeps the element in the normal flow but lets you offset it from its original position using top, right, bottom, left. The space it originally occupied is preserved — other elements behave as if it had not moved. Relative positioning is most commonly used as a positioning context for absolutely positioned children.

Absolute positioning removes the element from the normal flow entirely. It is positioned relative to its nearest positioned ancestor (any ancestor with a position value other than static). If no positioned ancestor exists, it is positioned relative to the initial containing block (usually the viewport). Other elements ignore its space.

Fixed positioning is like absolute, but relative to the viewport. The element stays in the same position even when the page scrolls. This is perfect for navigation bars, back-to-top buttons, and floating action buttons. Sticky positioning is a hybrid: the element behaves like relative until it reaches a scroll threshold, then it sticks like fixed until its container scrolls past.

Positioning Code

/* Relative: offset from normal position */
.parent {
  position: relative;  /* also creates positioning context */
}

/* Absolute: positioned within nearest positioned ancestor */
.tooltip {
  position: absolute;
  top: 100%;
  left: 50%;
  transform: translateX(-50%);
}

/* Fixed: stays in place during scroll */
.navbar {
  position: fixed;
  top: 0;
  left: 0;
  right: 0;
  z-index: 1000;
}

/* Sticky: sticks after scrolling past threshold */
.sidebar-title {
  position: sticky;
  top: 0;
}

4. Overflow

When content is larger than its container, the overflow property controls what happens. By default, content overflows visibly, spilling out of its box. This is often undesirable — you may want to clip the excess, add scrollbars, or show scrollbars only when needed.

visible (default) lets content overflow the box without clipping. hidden clips content at the box boundary — anything beyond is invisible and unreachable. scroll always shows scrollbars, even when the content fits. auto shows scrollbars only when the content actually overflows, which is usually the best choice for scrollable containers.

You can control horizontal and vertical overflow independently with overflow-x and overflow-y. This is useful for wide tables that need horizontal scrolling but not vertical, or for chat windows that need vertical scrolling only.

Overflow also creates a new block formatting context, which prevents margin collapsing and contains floated children. Setting overflow: hidden on a parent is a classic technique for containing floats, though modern layout methods (flexbox and grid) have largely replaced this pattern.

Overflow Behaviors

overflow: visible

This content is taller than its container. With overflow: visible, it spills out beyond the boundary of the box and overlaps whatever comes below it.

overflow: hidden

This content is taller than its container. With overflow: hidden, the excess content is clipped and completely invisible. Users cannot scroll to see it.

overflow: scroll

This content is taller than its container. With overflow: scroll, scrollbars always appear, even if the content fits. This can look odd on short content but guarantees scrollability.

overflow: auto

This content is taller than its container. With overflow: auto, scrollbars appear only when needed. This is the most common and user-friendly option for scrollable areas.

Overflow Code

/* Hide overflow */
.card-image {
  overflow: hidden;
  border-radius: 12px;
}

/* Scrollable container */
.chat-messages {
  overflow-y: auto;
  max-height: 400px;
}

/* Horizontal scroll for wide content */
.table-wrapper {
  overflow-x: auto;
  overflow-y: hidden;
}

5. Z-Index & Stacking

While most CSS layout is two-dimensional (horizontal and vertical), the z-index property controls the third dimension: the stacking order of overlapping elements. Elements with higher z-index values appear in front of elements with lower values. But z-index only works on positioned elements (anything other than position: static).

The concept of stacking contexts is crucial. A stacking context is a three-dimensional conceptualization of HTML elements along an imaginary z-axis. When an element creates a new stacking context, all of its children are stacked within that context. A z-index of 9999 on a child will never appear above a sibling of its parent that has a higher stacking order.

Stacking contexts are created by several CSS properties: any positioned element with a z-index value other than auto, elements with opacity less than 1, elements with transform, filter, or will-change properties, and flex/grid children with z-index values. Understanding this prevents the common confusion of "why is my z-index: 99999 not working?"

In practice, use a structured z-index scale: define layers in your CSS (e.g., base content at 1, dropdowns at 100, modals at 200, tooltips at 300, notifications at 400). This prevents the arms race of ever-increasing z-index values and keeps your stacking predictable.

Why Z-Index Values Should Be Systematic

Without a system, z-index values escalate wildly: one developer uses 10, another uses 100 to go above it, then someone uses 9999. Soon you have z-index: 2147483647 (the max 32-bit integer) and nowhere to go. Define a layer system with clear ranges: base (1-9), navigation (10-19), dropdowns (20-29), modals (30-39), tooltips (40-49). This creates order and makes debugging effortless.

Z-Index System

/* Define z-index layers with custom properties */
:root {
  --z-base: 1;
  --z-dropdown: 100;
  --z-sticky: 200;
  --z-modal-backdrop: 300;
  --z-modal: 400;
  --z-tooltip: 500;
  --z-notification: 600;
}

.dropdown-menu {
  position: absolute;
  z-index: var(--z-dropdown);
}

.modal-overlay {
  position: fixed;
  z-index: var(--z-modal-backdrop);
}

.modal {
  position: fixed;
  z-index: var(--z-modal);
}

Exercise: Fixed Nav & Sticky Sidebar

Build a page layout with the following features:

  • A fixed navigation bar at the top of the page that stays visible when scrolling. It should have a background color, padding, and a z-index high enough to stay above all content.
  • Add enough padding-top to the body or main content so it is not hidden behind the fixed nav.
  • Create a two-column layout: a main content area (wider) and a sidebar (narrower).
  • Make the sidebar sticky so it stays visible as the user scrolls through the main content. Set position: sticky and top to the height of your fixed nav.
  • Add enough content in the main area (multiple paragraphs or sections) to enable scrolling.
  • Ensure the layout works with box-sizing: border-box applied globally.

Challenge: Layered Card Stack

Create a visually striking card stack effect:

  • Create 5 cards that overlap each other, each offset slightly to the right and down from the one below it.
  • Each card should have an increasing z-index so the last card appears on top.
  • Give each card a different background color (use HSL with the same hue but varying lightness).
  • The top card (highest z-index) should have a prominent box-shadow to make it "pop" from the stack.
  • Use position: absolute for the cards within a position: relative container.
  • On hover, each card should increase its z-index and scale up slightly with a smooth transition, rising above the stack.

Bonus: Add a transform: rotate() to each card with slightly different angles (e.g., -3deg, -1.5deg, 0deg, 1.5deg, 3deg) to create a fanned-out effect.
