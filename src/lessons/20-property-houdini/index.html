@property & Houdini Animations

Give the browser a type system for your custom properties. When CSS knows that --hue is an angle and --progress is a number, it can interpolate between values instead of snapping. The result: gradient animations, number tickers, and choreographed sequences that were previously impossible without JavaScript.

1. The @property Rule

Custom properties registered with var(--name) are incredibly useful, but the browser treats them as opaque strings. It has no idea whether --gap: 2rem is a length, a color, or just text. That means it cannot transition between two values of a custom property—it can only swap them instantly.

The @property rule changes everything. It tells the browser the type of your custom property, whether it inherits, and what its default value should be. Once the browser understands the type, it can interpolate smoothly between values during transitions and animations.

Anatomy of @property

CSS

@property --hue {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

@property --card-color {
  syntax: "<color>";
  inherits: true;
  initial-value: #6c5ce7;
}

@property --progress {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

Three descriptors, all required:

  • syntax — declares the type. Must be a quoted string containing a CSS value definition syntax. Common types: "<color>", "<length>", "<number>", "<percentage>", "<angle>", "<integer>", "<length-percentage>", or "*" for any value (universal, but loses interpolation).
  • inherits — true or false. Controls whether child elements inherit the property value from their parent. Most animation properties should be false.
  • initial-value — the default value when the property is not explicitly set. Must be valid for the declared syntax. Required for all syntax types except "*".

Available Syntax Types

<color> Any CSS color value #ff0, oklch(0.7 0.15 200)
<length> Dimension with length units 0px, 2rem, 50vw
<number> Floating-point number 0, 1.5, 3.14
<percentage> Percentage value 0%, 50%, 100%
<angle> Angle value 0deg, 180deg, 1turn
<integer> Whole number (no decimals) 0, 42, 100
Key Insight: Without @property, custom properties are always treated as strings. Setting --color: red and then transitioning to --color: blue will cause an instant snap. With @property and syntax: "<color>", the browser knows it can interpolate through the color space. This single rule unlocks an entire category of previously impossible CSS animations.

2. Animating Custom Properties

The moment you register a custom property with @property, it becomes animatable. This is the single most impactful thing @property enables. Colors blend, numbers count, angles rotate, lengths grow—all driven purely by CSS transitions and keyframes.

Transitioning Colors

Consider a card that shifts its accent color on hover. Without @property, this requires animating a real CSS property like background or box-shadow directly. With @property, you animate the variable and let it cascade naturally into every place it is used.

CSS

@property --accent {
  syntax: "<color>";
  inherits: false;
  initial-value: #6c5ce7;
}

.card {
  --accent: #6c5ce7;
  border: 2px solid var(--accent);
  box-shadow: 0 4px 20px color-mix(in oklch, var(--accent) 30%, transparent);
  transition: --accent 0.6s ease;
}

.card:hover {
  --accent: #00cec9;
  /* Both border AND shadow transition together
     because they both reference --accent */
}

Keyframe Animations

Transitions respond to state changes (hover, focus, class toggles). But for continuous or multi-step animations, you need @keyframes. Registered custom properties work perfectly with keyframes too.

CSS

@property --hue {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

@keyframes hue-cycle {
  from { --hue: 0deg; }
  to   { --hue: 360deg; }
}

.element {
  background: oklch(0.7 0.15 var(--hue));
  animation: hue-cycle 4s linear infinite;
}
Key Insight: The real power here is indirection. You are not animating background directly—you are animating a variable that feeds into background, border, shadow, text color, or anything else. One animated variable can drive dozens of visual changes simultaneously.

3. Gradient Animations

Before @property, gradients were completely static. You could not transition between two gradients because CSS had no way to interpolate color stops or angles within a gradient function. The only workaround was opacity-fading between two elements with different background gradients.

With registered custom properties, you can animate individual parameters within a gradient: the angle, color stops, or position values. This opens up spectacular effects that previously required canvas or WebGL.

Rotating Conic Gradients

CSS

@property --angle {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

@keyframes spin-gradient {
  to { --angle: 360deg; }
}

.spinner {
  background: conic-gradient(
    from var(--angle),
    #6c5ce7,
    #00cec9,
    #fdcb6e,
    #6c5ce7
  );
  animation: spin-gradient 3s linear infinite;
}

Color-Cycling Backgrounds

By registering multiple color custom properties, you can cycle an entire gradient palette through a smooth animation loop.

CSS

@property --color-1 {
  syntax: "<color>";
  inherits: false;
  initial-value: #6c5ce7;
}

@property --color-2 {
  syntax: "<color>";
  inherits: false;
  initial-value: #00cec9;
}

@keyframes gradient-cycle {
  0%   { --color-1: #6c5ce7; --color-2: #00cec9; }
  33%  { --color-1: #fd79a8; --color-2: #fdcb6e; }
  66%  { --color-1: #00b894; --color-2: #0984e3; }
  100% { --color-1: #6c5ce7; --color-2: #00cec9; }
}

.hero {
  background: linear-gradient(135deg, var(--color-1), var(--color-2));
  animation: gradient-cycle 8s ease infinite;
}

4. Counter Animations

One of the most visually striking uses of @property is animating numbers. By registering a property with syntax: "<integer>", you can animate from 0 to any target value. Combined with counter-set and CSS counter(), you get a pure CSS number ticker—no JavaScript needed.

The Technique

CSS

@property --count {
  syntax: "<integer>";
  inherits: false;
  initial-value: 0;
}

@keyframes count-up {
  to { --count: 100; }
}

.ticker {
  animation: count-up 2s ease-out forwards;
  counter-set: num var(--count);
}

.ticker::after {
  content: counter(num);
}

How it works step by step:

  1. @property registers --count as an integer, enabling interpolation.
  2. @keyframes count-up animates --count from 0 to 100.
  3. counter-set feeds the animated value into a CSS counter named num.
  4. The ::after pseudo-element displays the counter with content: counter(num).
  5. Because the browser interpolates integers, you see every whole number from 0 to 100 during the animation.

Percentage Bars with Animated Values

The same technique can combine a growing progress bar with a live-updating label showing the percentage:

CSS

@property --bar-pct {
  syntax: "<integer>";
  inherits: false;
  initial-value: 0;
}

@keyframes fill-bar {
  to { --bar-pct: var(--target-pct); }
}

.progress-bar {
  /* Animate both the bar width and the counter */
  animation: fill-bar 1.5s ease-out forwards;
  counter-set: pct var(--bar-pct);
}

.progress-bar::after {
  content: counter(pct) "%";
}

.progress-bar::before {
  /* Use the same variable for the bar fill */
  width: calc(var(--bar-pct) * 1%);
}

5. Complex Choreography

When you register multiple custom properties, you can animate each one independently with its own timing, delay, and easing function. This is CSS choreography: sequenced, layered animations that create sophisticated motion design.

Staggered Multi-Property Transitions

CSS

@property --x-offset {
  syntax: "<length>";
  inherits: false;
  initial-value: -30px;
}

@property --blur {
  syntax: "<length>";
  inherits: false;
  initial-value: 10px;
}

@property --fade {
  syntax: "<number>";
  inherits: false;
  initial-value: 0;
}

.card {
  transform: translateX(var(--x-offset));
  filter: blur(var(--blur));
  opacity: var(--fade);

  /* Each property transitions at a different time */
  transition:
    --fade 0.4s ease 0s,
    --blur 0.5s ease 0.1s,
    --x-offset 0.6s cubic-bezier(0.22, 1, 0.36, 1) 0.15s;
}

.card.visible {
  --x-offset: 0px;
  --blur: 0px;
  --fade: 1;
}

Notice the staggered transition-delay values: opacity starts immediately, blur begins 100ms later, and position follows at 150ms. This creates a natural "unfurling" effect where the element fades in, sharpens, then slides into place.

Combining with Scroll-Driven Animations

Registered custom properties pair beautifully with scroll-driven animations. You can bind @property variables to scroll progress using animation-timeline: scroll() or view(), creating scroll-linked effects with smooth interpolation.

CSS

@property --scroll-hue {
  syntax: "<angle>";
  inherits: false;
  initial-value: 0deg;
}

@property --scroll-scale {
  syntax: "<number>";
  inherits: false;
  initial-value: 0.8;
}

@keyframes scroll-reveal {
  from {
    --scroll-hue: 0deg;
    --scroll-scale: 0.8;
  }
  to {
    --scroll-hue: 120deg;
    --scroll-scale: 1;
  }
}

.scroll-card {
  background: oklch(0.6 0.15 var(--scroll-hue));
  transform: scale(var(--scroll-scale));
  animation: scroll-reveal linear both;
  animation-timeline: view();
  animation-range: entry 20% cover 50%;
}
Key Insight: The choreography approach lets you compose complex motion from simple building blocks. Each @property variable is one "track" in your animation timeline. You control each track's duration, easing, and delay independently, then the browser composites the result. This is the same mental model used in professional motion design tools.

6. Houdini Paint API (Overview)

The @property rule is actually part of a larger initiative called CSS Houdini—a set of APIs that expose CSS engine internals to developers. While @property has achieved universal browser support, the Paint API is the other Houdini feature worth understanding.

What is the Paint API?

The Paint API lets you write JavaScript that generates custom images for CSS properties like background-image, border-image, and mask-image. You register a "paint worklet" and then reference it in CSS with the paint() function.

JavaScript (paint-worklet.js)

// Register a paint worklet
class CirclesPainter {
  // Declare which CSS properties the worklet reads
  static get inputProperties() {
    return ['--circle-count', '--circle-color'];
  }

  paint(ctx, size, properties) {
    const count = properties.get('--circle-count').toString() | 0;
    const color = properties.get('--circle-color').toString();

    ctx.fillStyle = color;

    for (let i = 0; i < count; i++) {
      const x = Math.random() * size.width;
      const y = Math.random() * size.height;
      const r = Math.random() * 20 + 5;

      ctx.beginPath();
      ctx.arc(x, y, r, 0, Math.PI * 2);
      ctx.fill();
    }
  }
}

registerPaint('circles', CirclesPainter);

CSS + HTML

/* Register the properties for animation */
@property --circle-count {
  syntax: "<integer>";
  inherits: false;
  initial-value: 20;
}

/* Load the worklet */
/* <script>CSS.paintWorklet.addModule('paint-worklet.js')</script> */

.generative-bg {
  background-image: paint(circles);
  --circle-count: 40;
  --circle-color: rgba(108, 92, 231, 0.3);

  /* Animate the count! */
  transition: --circle-count 1s ease;
}

.generative-bg:hover {
  --circle-count: 100;
}

Paint API + @property = Animated Generative Art

The magic happens when you combine the Paint API with @property. Register a custom property that the paint worklet reads, then animate that property. The worklet re-renders on every frame with the interpolated value. This gives you animated, procedural, GPU-accelerated backgrounds with CSS control.

Key Insight: While the Paint API is limited to Chromium browsers (Chrome, Edge, Opera), @property itself is fully supported across all modern browsers including Firefox and Safari. Focus your production work on @property and treat the Paint API as a progressive enhancement for Chromium users.

7. Progressive Enhancement

Although @property has excellent browser support in 2026, you should still write defensive CSS. The @supports at-rule can detect @property support, and you can layer your animations so that non-supporting browsers get a functional (if less flashy) experience.

Feature Detection

CSS

/* Base styles: always work */
.card {
  background: linear-gradient(135deg, #6c5ce7, #00cec9);
  transition: opacity 0.3s ease;
}

/* Enhanced: only if @property is supported */
@supports (--custom: 0) and (animation-timeline: scroll()) {
  @property --gradient-angle {
    syntax: "<angle>";
    inherits: false;
    initial-value: 135deg;
  }

  .card {
    background: linear-gradient(
      var(--gradient-angle), #6c5ce7, #00cec9
    );
    animation: rotate-gradient 4s linear infinite;
  }

  @keyframes rotate-gradient {
    to { --gradient-angle: 495deg; }
  }
}

Testing @property Support Specifically

CSS

/* The most reliable test for @property support */
@supports (background: paint(something)) {
  /* Paint API supported (Chromium) */
}

/* For @property specifically, test with initial-value */
@supports at-rule(@property) {
  /* @property is supported */
  /* Apply enhanced animated gradients, counters, etc. */
}

The Fallback Pattern

CSS

/* 1. Start with a static fallback */
.hero {
  background: linear-gradient(135deg, #6c5ce7, #00cec9);
}

/* 2. If @property works, override with animated version */
@property --hero-c1 {
  syntax: "<color>";
  inherits: false;
  initial-value: #6c5ce7;
}

@property --hero-c2 {
  syntax: "<color>";
  inherits: false;
  initial-value: #00cec9;
}

.hero {
  background: linear-gradient(135deg, var(--hero-c1), var(--hero-c2));
  animation: hero-colors 6s ease infinite alternate;
}

@keyframes hero-colors {
  to {
    --hero-c1: #fd79a8;
    --hero-c2: #fdcb6e;
  }
}

/* Browsers that don't support @property will ignore
   the @property rules, use the fallback gradient,
   and silently skip the animation. */
Key Insight: The beauty of @property progressive enhancement is that it degrades gracefully by design. If a browser ignores @property, the custom properties still work as untyped variables—they just will not animate. Your layout and colors remain correct; you only lose the animation. This makes @property one of the safest modern CSS features to adopt.
