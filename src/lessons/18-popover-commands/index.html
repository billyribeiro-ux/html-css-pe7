Popover & Invoker Commands

Build tooltips, dropdowns, notification panels, and confirmation dialogs using nothing but HTML attributes and CSS. The Popover API and Invoker Commands replace hundreds of lines of JavaScript with declarative markup that is accessible, composable, and light-dismiss-aware out of the box.

1. Popover Basics

The Popover API introduces a native way to display overlay content — tooltips, menus, dialogs, pickers, teaching UI — without writing a single line of JavaScript. At its core, you add the popover attribute to any element, then wire a button to it with popovertarget. The browser handles visibility, stacking context, focus management, and light-dismiss behavior automatically.

The popover Attribute

Any HTML element can become a popover by adding the popover attribute. The element starts hidden and is promoted to the top layer when opened — above all other content, including elements with z-index: 999999. No stacking-context wars, ever.

HTML

<!-- Auto popover: light-dismiss + only one open at a time -->
<div id="my-popup" popover>
  <p>I live in the top layer!</p>
</div>

<!-- Manual popover: no light-dismiss, multiple can coexist -->
<div id="sticky-popup" popover="manual">
  <p>I stay open until explicitly closed.</p>
</div>

Auto vs Manual

The popover attribute accepts two values:

  • popover or popover="auto" — Light-dismiss enabled: clicking outside, pressing Esc, or opening another auto-popover closes it. Only one auto-popover is visible at a time (unless nested).
  • popover="manual" — No light-dismiss. You must explicitly close it via a button or JavaScript. Multiple manual popovers can be open simultaneously.

Wiring Buttons with popovertarget

To control a popover, add popovertarget to a <button> pointing at the popover's ID. Optionally set popovertargetaction to show, hide, or toggle (toggle is the default).

HTML

<button popovertarget="info-popup">Toggle Info</button>
<button popovertarget="info-popup" popovertargetaction="show">Show</button>
<button popovertarget="info-popup" popovertargetaction="hide">Hide</button>

<div id="info-popup" popover>
  <h3>Information</h3>
  <p>This popover is controlled entirely by HTML attributes.</p>
  <button popovertarget="info-popup" popovertargetaction="hide">Close</button>
</div>

Key Insight: Popovers live in the browser's top layer — a special stacking context above everything else in the document. This means you never need to fight with z-index to keep a popover on top. The ::backdrop pseudo-element is also available, just like with <dialog>.

2. CSS for Popovers

Once you have the HTML wired up, CSS is where popovers become beautiful. The :popover-open pseudo-class, the ::backdrop pseudo-element, @starting-style, and transition-behavior: allow-discrete give you full control over entry and exit animations — without JavaScript or animation libraries.

:popover-open

The :popover-open pseudo-class matches a popover element when it is in the open (showing) state. This is the primary selector you use to style the visible state of your popover.

CSS

/* Hidden state (default) */
[popover] {
  opacity: 0;
  transform: scale(0.95) translateY(-8px);
  transition: opacity 0.25s, transform 0.25s,
              display 0.25s allow-discrete;
}

/* Open state */
[popover]:popover-open {
  opacity: 1;
  transform: scale(1) translateY(0);
}

::backdrop Styling

Just like <dialog>, popovers get a ::backdrop pseudo-element when promoted to the top layer. You can blur and dim the background behind your popover for a modal-like effect.

CSS

[popover]::backdrop {
  background: rgba(0, 0, 0, 0.4);
  backdrop-filter: blur(4px);
  transition: opacity 0.3s, display 0.3s allow-discrete;
  opacity: 0;
}

[popover]:popover-open::backdrop {
  opacity: 1;
}

Entry & Exit Animations with @starting-style

The @starting-style rule defines the initial values for a transition when an element first appears (enters the page or becomes visible). Without it, the browser has no "from" state to transition from, so the element would just pop into view.

CSS

/* The trick: @starting-style sets the "before" state
   for elements entering the page */
[popover]:popover-open {
  opacity: 1;
  transform: translateY(0);

  @starting-style {
    opacity: 0;
    transform: translateY(-12px);
  }
}

/* For exit transitions, you also need: */
[popover] {
  transition: opacity 0.2s, transform 0.2s,
              display 0.2s allow-discrete;
  opacity: 0;
  transform: translateY(-12px);
}

transition-behavior: allow-discrete

Normally, display cannot be animated — it jumps between values. The allow-discrete value on transition-behavior (or as a shorthand inside transition) tells the browser to keep the element visible during its exit transition before flipping display to none. This is essential for smooth exit animations on popovers.

CSS

/* Shorthand form: add allow-discrete after the duration */
[popover] {
  transition: opacity 0.3s ease,
              transform 0.3s ease,
              display 0.3s allow-discrete,
              overlay 0.3s allow-discrete;
}

Demo: Animated Popover with Backdrop

This popover fades and slides in using @starting-style and transitions out smoothly with allow-discrete. Notice the blurred backdrop behind it.

Key Insight: The overlay property should also be included in your transition list. It controls how long the element stays in the top layer during its exit animation. Without transitioning overlay, the popover might drop out of the top layer mid-animation and appear behind other content.

3. Invoker Commands

Invoker Commands are the next evolution of declarative HTML interactions. While popovertarget only works with popovers, the commandfor and command attributes create a general-purpose mechanism to trigger actions on any element — popovers, dialogs, details, custom elements, and more.

Syntax

HTML

<!-- commandfor + command replaces popovertarget + popovertargetaction -->
<button commandfor="my-popover" command="toggle-popover">
  Toggle Popover
</button>

<button commandfor="my-dialog" command="show-modal">
  Open Dialog
</button>

<button commandfor="my-dialog" command="close">
  Close Dialog
</button>

Built-in Command Values

The command attribute supports several built-in actions depending on the target element type:

Command Target Behavior
toggle-popover Popover element Toggles the popover open/closed
show-popover Popover element Opens the popover (no-op if already open)
hide-popover Popover element Closes the popover
show-modal <dialog> Opens the dialog as modal
close <dialog> Closes the dialog, optionally with a return value
--custom-name Any element Fires a command event on the target for JS handling

HTML

<!-- A complete dialog flow with no JavaScript -->
<button commandfor="confirm-dialog" command="show-modal">
  Delete Account
</button>

<dialog id="confirm-dialog">
  <h3>Are you sure?</h3>
  <p>This action cannot be undone.</p>
  <div class="dialog-actions">
    <button commandfor="confirm-dialog" command="close">Cancel</button>
    <button commandfor="confirm-dialog" command="close" value="confirm">
      Confirm Delete
    </button>
  </div>
</dialog>

Demo: Invoker Commands in Action

Key Insight: Custom commands (prefixed with --) let you fire events declaratively. For example, command="--add-to-cart" dispatches a command event on the target element with the command property set to "--add-to-cart". You handle it once in JavaScript, and the HTML stays clean and semantic.

4. Interest Invokers

Interest Invokers bring hover and focus-triggered popovers to HTML — the interesttarget attribute. Point it at a popover, and the browser shows the popover on hover or focus and hides it when interest is lost. This is how you build tooltips without JavaScript.

Syntax

HTML

<!-- Tooltip appears on hover/focus, disappears on leave/blur -->
<button interesttarget="tooltip-1">Hover me</button>

<div id="tooltip-1" popover="hint" class="tooltip">
  I appear on hover and focus!
</div>

The popover="hint" value is a third popover mode designed specifically for non-interactive overlays like tooltips. It does not steal focus, does not affect other popovers, and dismisses automatically when interest is lost.

How Interest Works

  • Mouse: Hovering over the trigger element shows the popover. Moving the mouse away hides it (after a brief grace period).
  • Keyboard: Focusing the trigger with Tab shows the popover. Blurring hides it.
  • Touch: Long-press shows the popover on touch devices.
  • Accessibility: Screen readers announce the popover content as a description of the trigger element.

5. Anchor Positioning with Popovers

The CSS Anchor Positioning API lets you position a popover relative to the element that triggered it — no JavaScript required. By combining anchor-name, position-anchor, and position-area, you create floating elements that stay perfectly attached to their anchors as the page scrolls or resizes.

Setting Up Anchors

CSS

/* Step 1: Name the anchor element */
.trigger-btn {
  anchor-name: --my-trigger;
}

/* Step 2: Attach the popover to the anchor */
.my-popover {
  position-anchor: --my-trigger;

  /* Step 3: Position relative to the anchor */
  position-area: block-end;   /* Below the trigger */
  margin-top: 8px;
}

position-area Values

The position-area property uses a grid-based model to place elements relative to their anchor. Think of the anchor as the center of a 3x3 grid:

/* Common positioning patterns */
.tooltip-above {
  position-anchor: --trigger;
  position-area: block-start;       /* Centered above */
}

.dropdown-below {
  position-anchor: --trigger;
  position-area: block-end;         /* Centered below */

  position-anchor: --trigger;
  position-area: inline-end;        /* To the right */

.smart-tooltip {
  position-anchor: --trigger;
  position-area: block-start;
  position-try-fallbacks: flip-block, flip-inline, flip-block flip-inline;
}

6. Patterns: No-JS UI Components

The Popover API, Invoker Commands, and Anchor Positioning combine to create production-ready UI patterns that previously required JavaScript frameworks. Here are the most common patterns, all built with pure HTML and CSS.

Pattern 1: Dropdown Menu

HTML

<nav class="dropdown">
  <button popovertarget="file-menu"
          style="anchor-name: --file-btn;">
    File
  </button>
  <div id="file-menu" popover
       class="dropdown-panel"
       style="position-anchor: --file-btn;">
    <button>New File</button>
    <button>Open</button>
    <button>Save</button>
    <hr>
    <button>Exit</button>
  </div>
</nav>

7. Progressive Enhancement

Although the Popover API has been shipping in all major browsers since 2024, Invoker Commands and Interest Invokers are newer. Good progressive enhancement ensures your UI works everywhere and gets better in capable browsers.

Feature Detection

CSS

/* Detect popover support */
@supports selector(:popover-open) {
  /* Safe to use popover-specific styles */
  [popover] {
    transition: opacity 0.3s, transform 0.3s,
                display 0.3s allow-discrete;
  }
}

/* Detect anchor positioning */
@supports (anchor-name: --x) {
  .tooltip {
    position-anchor: --trigger;
    position-area: block-start;
  }
}

/* Detect @starting-style */
@supports (transition-behavior: allow-discrete) {
  [popover]:popover-open {
    @starting-style {
      opacity: 0;
      transform: scale(0.95);
    }
  }
}

Fallback Patterns

HTML

<!-- Tooltip fallback: use title attribute -->
<button
  interesttarget="tt-info"
  title="Detailed tooltip content for older browsers"
>
  Info
</button>
<div id="tt-info" popover class="tooltip">
  Rich tooltip with formatting and links.
</div>

<!-- Dropdown fallback: use details/summary -->
<details class="dropdown-fallback">
  <summary>Menu</summary>
  <ul>
    <li><a href="#">Option 1</a></li>
    <li><a href="#">Option 2</a></li>
  </ul>
</details>

CSS

/* Hide fallback when popover is supported */
@supports selector(:popover-open) {
  .dropdown-fallback {
    display: none;
  }
}

/* Show fallback only when popover is NOT supported */
@supports not selector(:popover-open) {
  [popover] {
    /* Make popover behave like a regular positioned element */
    display: none;
    position: absolute;
  }

  [popover].is-open {
    display: block;
  }
}

Create a user avatar button that opens a profile popover below it. The popover should include the user's name, email, role, and action buttons. Use anchor positioning to keep it attached to the avatar.

Requirements

  • Create an avatar button with popovertarget pointing to a profile popover.
  • Add anchor-name to the avatar and position-anchor + position-area: block-end to the popover.
  • Style the popover with a smooth entry animation using @starting-style and transition-behavior: allow-discrete.
  • Include a ::backdrop with a subtle blur effect.
  • Add a "Sign Out" button inside the popover that closes it using popovertargetaction="hide".
  • Make the popover auto so it light-dismisses on outside click.
  • Wrap your animations in @supports selector(:popover-open) for progressive enhancement.

Challenge: Mega-Menu Navigation

Build a full mega-menu navigation bar with multiple dropdown panels, all using the Popover API, anchor positioning, and animated transitions. No JavaScript allowed.

Requirements

  • Navigation bar: At least 4 top-level menu items. Each one is a <button> with popovertarget pointing to its panel.
  • Mega-menu panels: Each panel should have a multi-column layout (use CSS Grid). Include icons, headings, descriptions, and links.
  • Anchor positioning: Each panel should be anchored below its trigger button using anchor-name and position-area: block-end.
  • Animations: Panels should fade and slide in from above with @starting-style. Use transition-behavior: allow-discrete for smooth exit animations.
  • Auto-dismiss: Use popover="auto" so only one panel is open at a time and clicking outside closes it.
  • Backdrop: Add a subtle ::backdrop that dims the page behind the mega-menu.
  • Responsive: On narrow screens, collapse into a single hamburger button that opens a full-width popover panel.

Architecture Hints

  • Give each trigger a unique anchor-name (e.g., --nav-products, --nav-solutions).
  • Use position-area: block-end span-inline-end for left-aligned panels that extend rightward from their trigger.
  • For the mega-menu grid, grid-template-columns: repeat(3, 1fr) works well with category sections inside.
  • Add position-try-fallbacks: flip-block so panels flip above the nav if there is not enough room below.
  • Use <nav> with aria-label for the menu bar, and group links with role="group" in each panel.
