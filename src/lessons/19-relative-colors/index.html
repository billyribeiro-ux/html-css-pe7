Relative Colors & contrast-color()

Derive entire palettes from a single base color. Lighten, darken, shift hue, adjust alpha — all in pure CSS. Then let the browser pick accessible text colors for you with contrast-color(). One custom property in, a complete design system out.

1. Relative Color Syntax

Module 11 taught you OKLCH, color-mix, and the foundations of modern color in CSS. Relative color syntax is the next leap: instead of defining every color from scratch, you derive new colors from existing ones. You take a base color and say "give me the same hue but lighter" or "same color, half the chroma." The browser does the math.

The from Keyword

The magic word is from. It goes inside any color function and tells the browser to decompose an origin color into its channels, which you can then reference and manipulate individually.

CSS

/* Basic syntax: oklch(from <origin> L C H) */
--base: oklch(0.65 0.2 265);

/* Reference channels directly */
--same-color: oklch(from var(--base) l c h);

/* Works in any color function */
--via-hsl: hsl(from var(--base) h s l);
--via-lab: lab(from var(--base) l a b);
--via-lch: lch(from var(--base) l c h);

/* The origin can be any valid color */
--from-hex: oklch(from #6c5ce7 l c h);
--from-named: oklch(from rebeccapurple l c h);
--from-rgb: oklch(from rgb(108 92 231) l c h);

Channel References

When you use from, the browser converts the origin color into the target color space and exposes each channel as a single-letter variable. In OKLCH, those are l (lightness, 0–1), c (chroma, 0–0.4), and h (hue, 0–360). You can use them as-is, wrap them in calc(), or replace them with constants.

CSS

--brand: oklch(0.65 0.2 265);

/* Use channel references directly */
--identical: oklch(from var(--brand) l c h);

/* Replace one channel */
--lighter: oklch(from var(--brand) 0.85 c h);

/* Compute from the channel */
--lighter-calc: oklch(from var(--brand) calc(l + 0.2) c h);

/* Mix and match */
--muted-shifted: oklch(from var(--brand) l calc(c * 0.5) calc(h + 30));
Key Insight: The channel variables (l, c, h, s, etc.) are only available inside the color function that uses from. They are not custom properties — they are ephemeral references scoped to that single declaration. You cannot use l outside of a relative color expression.

2. Channel Manipulation

The real power of relative colors is calc() on individual channels. You are not limited to swapping in constants — you can scale, offset, clamp, and compose channel values with full CSS math. This is how you build an entire tonal palette from one line of CSS.

Lightening & Darkening

CSS

--base: oklch(0.55 0.2 265);

/* Lighten by adding to L */
--light-10: oklch(from var(--base) calc(l + 0.10) c h);
--light-20: oklch(from var(--base) calc(l + 0.20) c h);
--light-30: oklch(from var(--base) calc(l + 0.30) c h);

/* Darken by subtracting from L */
--dark-10: oklch(from var(--base) calc(l - 0.10) c h);
--dark-20: oklch(from var(--base) calc(l - 0.20) c h);

/* Scale lightness (multiplicative) */
--lighter: oklch(from var(--base) calc(l * 1.3) c h);
--darker:  oklch(from var(--base) calc(l * 0.7) c h);

Hue Shifting

CSS

--base: oklch(0.65 0.2 265);

/* Analogous colors: shift by 30 degrees */
--analog-left:  oklch(from var(--base) l c calc(h - 30));
--analog-right: oklch(from var(--base) l c calc(h + 30));

/* Complementary: shift by 180 degrees */
--complement: oklch(from var(--base) l c calc(h + 180));

/* Triadic: shift by 120 degrees */
--triad-1: oklch(from var(--base) l c calc(h + 120));
--triad-2: oklch(from var(--base) l c calc(h + 240));

Chroma (Saturation) Control

CSS

--base: oklch(0.65 0.2 265);

/* Desaturate by scaling chroma */
--muted:  oklch(from var(--base) l calc(c * 0.5) h);
--pastel: oklch(from var(--base) l calc(c * 0.3) h);
--gray:   oklch(from var(--base) l 0 h);

/* Boost saturation */
--vivid: oklch(from var(--base) l calc(c * 1.5) h);

Alpha Manipulation

CSS

--base: oklch(0.65 0.2 265);

/* Add transparency */
--semi:     oklch(from var(--base) l c h / 0.5);
--ghost:    oklch(from var(--base) l c h / 0.15);
--overlay:  oklch(from var(--base) l c h / 0.8);

/* Use HSL if you prefer */
--hsl-semi: hsl(from var(--base) h s l / 50%);

Key Insight: OKLCH channel values are automatically clamped to valid ranges by the browser. If calc(l + 0.5) exceeds 1.0, it is clamped to 1.0 (pure white). 3. contrast-color()

Picking text colors that are readable against arbitrary backgrounds has always been painful. Dark background? White text. Light background? Black text. Somewhere in between? Break out the contrast calculator. contrast-color() eliminates that guesswork entirely. You give it a background color and it returns a text color that meets WCAG contrast requirements.

Syntax

CSS

/* Automatic: returns black or white for best contrast */
color: contrast-color(var(--bg));

/* Against a specific background */
.badge {
  --bg: oklch(0.55 0.2 265);
  background: var(--bg);
  color: contrast-color(var(--bg));
}

/* Works with any color format */
color: contrast-color(#6c5ce7);
color: contrast-color(rgb(108 92 231));
color: contrast-color(oklch(0.65 0.2 265));

Why This Matters

Before contrast-color(), building a badge component that accepted arbitrary user-chosen colors was a nightmare. You either limited colors to a safe set, or you wrote JavaScript to compute relative luminance and pick text color at runtime. Now the browser handles it natively.

CSS

/* The accessible badge pattern: one line does it all */
.tag {
  --tag-color: var(--color, oklch(0.55 0.2 265));
  background: var(--tag-color);
  color: contrast-color(var(--tag-color));
  padding: 0.25em 0.75em;
  border-radius: 999px;
  font-weight: 600;
}

/* Usage in HTML: any color, guaranteed readable text */
/* <span class="tag" style="--color: #e74c3c">Urgent</span> */
/* <span class="tag" style="--color: #f1c40f">Pending</span> */
/* <span class="tag" style="--color: #2ecc71">Done</span>    */

4. Palette Generation

The killer application of relative colors is building complete design system palettes from a single base color. Instead of hand-picking 10 shades of your brand blue, you define one --brand and derive every tint, shade, and surface from it. Change the base, and the entire system updates.

Tint & Shade Scale

CSS

:root {
  --brand: oklch(0.55 0.22 265);

  /* Tints: increase lightness, decrease chroma */
  --brand-50:  oklch(from var(--brand) 0.97 calc(c * 0.1) h);
  --brand-100: oklch(from var(--brand) 0.93 calc(c * 0.2) h);
  --brand-200: oklch(from var(--brand) 0.87 calc(c * 0.35) h);
  --brand-300: oklch(from var(--brand) 0.78 calc(c * 0.55) h);
  --brand-400: oklch(from var(--brand) 0.68 calc(c * 0.8) h);

  /* Base */
  --brand-500: var(--brand);

  /* Shades: decrease lightness, slightly decrease chroma */
  --brand-600: oklch(from var(--brand) calc(l - 0.06) calc(c * 0.95) h);
  --brand-700: oklch(from var(--brand) calc(l - 0.13) calc(c * 0.85) h);
  --brand-800: oklch(from var(--brand) calc(l - 0.20) calc(c * 0.70) h);
  --brand-900: oklch(from var(--brand) calc(l - 0.27) calc(c * 0.50) h);
  --brand-950: oklch(from var(--brand) calc(l - 0.33) calc(c * 0.30) h);
}

Semantic Palette from Brand

You can generate success, warning, and danger colors by hue-shifting your brand color. This keeps the entire palette feeling cohesive because chroma and lightness relationships remain consistent.

CSS

:root {
  --brand: oklch(0.55 0.22 265);

  /* Derive semantic colors by hue-shifting the brand */
  --success: oklch(from var(--brand) 0.65 0.18 145);
  --warning: oklch(from var(--brand) 0.80 0.16 85);
  --danger:  oklch(from var(--brand) 0.60 0.22 25);
  --info:    oklch(from var(--brand) 0.65 0.14 230);

  /* Surface colors from the brand's own hue */
  --surface-1: oklch(from var(--brand) 0.15 calc(c * 0.08) h);
  --surface-2: oklch(from var(--brand) 0.20 calc(c * 0.06) h);
  --surface-3: oklch(from var(--brand) 0.25 calc(c * 0.04) h);
}

5. Dark Mode from One Palette

The traditional approach to dark mode requires maintaining two complete sets of color tokens. With relative colors, you can derive dark mode from the same base — invert lightness, reduce chroma slightly, and you are done. The palette transforms itself.

The Lightness Inversion Technique

CSS

:root {
  --brand: oklch(0.55 0.22 265);

  /* Light mode surfaces */
  --bg:       oklch(from var(--brand) 0.98 calc(c * 0.02) h);
  --surface:  oklch(from var(--brand) 0.95 calc(c * 0.04) h);
  --text:     oklch(from var(--brand) 0.15 calc(c * 0.03) h);
  --muted:    oklch(from var(--brand) 0.45 calc(c * 0.05) h);

  /* Accent stays the same */
  --accent: var(--brand);
}

/* Dark mode: flip lightness values */
@media (prefers-color-scheme: dark) {
  :root {
    --bg:      oklch(from var(--brand) 0.12 calc(c * 0.04) h);
    --surface: oklch(from var(--brand) 0.18 calc(c * 0.06) h);
    --text:    oklch(from var(--brand) 0.92 calc(c * 0.03) h);
    --muted:   oklch(from var(--brand) 0.65 calc(c * 0.05) h);

    /* Accent brightens slightly in dark mode */
    --accent:  oklch(from var(--brand) calc(l + 0.1) c h);
  }
}

6. Gamut Mapping

When you manipulate color channels with calc(), you might push a color outside the gamut of the target color space. What happens when calc(c * 2) demands a chroma that sRGB simply cannot display? The browser performs gamut mapping — it finds the closest displayable color automatically.

How Gamut Mapping Works

CSS

/* This chroma is too high for sRGB */
--hyper-saturated: oklch(0.65 0.35 265);
/* Browser maps it to the nearest sRGB color automatically */

/* For wide-gamut displays, use display-p3 */
--wide-gamut: color(display-p3 0.3 0.2 0.9);

/* Relative colors work with display-p3 too */
--p3-lighter: oklch(from var(--wide-gamut) calc(l + 0.15) c h);

/* Check for wide gamut support */
@media (color-gamut: p3) {
  :root {
    --brand: oklch(0.55 0.28 265); /* higher chroma on P3 */
  }
}

Key Insight: Gamut mapping is lossy. If you push a color to oklch(0.65 0.35 265) on an sRGB display, the browser will clamp chroma to the sRGB boundary — roughly c: 0.24 for that hue/lightness. The mapped color is a visual approximation, not the original. Use @media (color-gamut: p3) to provide enhanced colors only to displays that can render them.

7. Practical Patterns

Relative colors and contrast-color() are not theoretical luxuries. They solve real, everyday UI problems. Here are the patterns you will reach for constantly.

Hover & Active States

CSS

.btn {
  --btn-color: oklch(0.55 0.22 265);
  background: var(--btn-color);
  color: contrast-color(var(--btn-color));
}

/* Darken by 10% on hover */
.btn:hover {
  background: oklch(from var(--btn-color) calc(l - 0.07) calc(c * 1.05) h);
}

/* Darken more on active / press */
.btn:active {
  background: oklch(from var(--btn-color) calc(l - 0.12) c h);
}

Disabled States

CSS

.btn:disabled {
  /* Reduce chroma (desaturate) and increase lightness */
  background: oklch(from var(--btn-color) calc(l + 0.15) calc(c * 0.3) h);
  color: oklch(from var(--btn-color) calc(l + 0.05) calc(c * 0.2) h);
  cursor: not-allowed;
  opacity: 0.7;
}

Focus Rings

CSS

.btn:focus-visible {
  /* Translucent version of button color for focus ring */
  outline: 3px solid oklch(from var(--btn-color) l c h / 0.5);
  outline-offset: 2px;
}

Status Colors from Brand

CSS

:root {
  --brand: oklch(0.55 0.22 265);
}

/* Derive every status color from brand, keeping visual harmony */
.alert--success {
  --alert-color: oklch(from var(--brand) 0.70 0.16 145);
  background: oklch(from var(--alert-color) 0.95 calc(c * 0.3) h);
  border-left: 4px solid var(--alert-color);
  color: oklch(from var(--alert-color) 0.25 calc(c * 0.5) h);
}

.alert--warning {
  --alert-color: oklch(from var(--brand) 0.82 0.14 85);
  background: oklch(from var(--alert-color) 0.96 calc(c * 0.4) h);
  border-left: 4px solid var(--alert-color);
  color: oklch(from var(--alert-color) 0.30 calc(c * 0.6) h);
}

.alert--danger {
  --alert-color: oklch(from var(--brand) 0.60 0.22 25);
  background: oklch(from var(--alert-color) 0.95 calc(c * 0.3) h);
  border-left: 4px solid var(--alert-color);
  color: oklch(from var(--alert-color) 0.25 calc(c * 0.5) h);
}

Exercise: Build a Color System

Build a complete color system from a single base color. Define tints, shades, a complementary accent, and semantic status colors. Then apply them to a set of UI components using contrast-color() for automatic text readability.

Requirements

  • Start with a single --brand custom property using oklch().
  • Generate at least 5 tint/shade steps (e.g., 100, 300, 500, 700, 900) using relative color syntax with calc() on the lightness channel.
  • Create a complementary accent by hue-shifting +180 degrees.
  • Define --success, --warning, and --danger colors by hue-shifting the brand.
  • Build at least 3 badges that use contrast-color() for their text color.
  • Add a button with hover (darken 7%), active (darken 12%), and disabled (desaturate) states using relative colors.
  • Include a focus ring using a translucent version of the button color (/ 0.4 alpha).

Challenge: Adaptive Theme Engine

Build a theme engine that takes a single hue angle as input and generates an entire UI — backgrounds, surfaces, text, buttons, badges, alerts, and cards — all derived from that one hue using relative colors and contrast-color(). Include both light and dark mode variants.

Requirements

  • Single input: The entire theme must derive from one --hue custom property (a number from 0 to 360).
  • Base color: Construct --brand as oklch(0.55 0.22 var(--hue)).
  • Surfaces: Generate at least 3 surface levels (bg, surface-1, surface-2) from the brand using near-zero chroma and the brand's hue.
  • Text colors: Derive primary text and muted text from the brand hue using very low chroma and appropriate lightness.
  • Palette scale: Generate at least a 5-step tint/shade scale (100 through 900) and display it.
  • Complementary accent: Derive an accent at calc(var(--hue) + 180) and use it for secondary buttons or highlights.
  • Status colors: Derive success (hue 145), warning (hue 85), and danger (hue 25) colors, keeping the brand's chroma and lightness relationships.
  • Contrast text: All text on colored backgrounds must use contrast-color().
  • Dark mode: Include a dark variant (via a .dark class or media query) that inverts lightness while keeping the hue.
  • UI components: Display at least a card with heading/body/button, 3 status badges, and an alert.

Architecture Hints

  • Define all tokens in :root using relative colors so changing --hue cascades everywhere.
  • For surfaces, use extremely low chroma: oklch(0.15 0.01 var(--hue)) for dark backgrounds, oklch(0.97 0.01 var(--hue)) for light.
  • A good disabled state formula: oklch(from var(--color) calc(l + 0.15) calc(c * 0.3) h).
  • Use color-mix() alongside relative colors for overlays: color-mix(in oklch, var(--brand) 10%, transparent).
  • Test your engine by changing --hue to 0 (red), 145 (green), 265 (blue), and 330 (pink). Everything should look harmonious at every hue.
