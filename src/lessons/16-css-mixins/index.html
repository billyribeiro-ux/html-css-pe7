CSS Mixins & @apply

Declare reusable style blocks with @mixin, apply them with @apply, compose design system primitives, and understand when mixins beat functions. Native CSS finally gets the pattern that preprocessors made indispensable.

1. @mixin Definition

A CSS mixin is a named, reusable block of declarations. You define one with @mixin, give it a dashed-ident name (like custom properties), and fill it with the styles you want to reuse. Think of it as a stamp: define the stamp once, press it anywhere.

Basic Syntax

CSS

/* Define a mixin */
@mixin --visually-hidden {
  position: absolute;
  width: 1px;
  height: 1px;
  padding: 0;
  margin: -1px;
  overflow: hidden;
  clip-path: inset(50%);
  white-space: nowrap;
  border: 0;
}

/* Another mixin: a card surface */
@mixin --card-surface {
  background: var(--surface, #1a1d27);
  border: 1px solid var(--border, #2e3345);
  border-radius: 12px;
  box-shadow: 0 4px 24px rgba(0, 0, 0, 0.3);
}

Parameters & Defaults

Mixins accept parameters using the same --dashed-ident syntax as custom properties. You can set defaults right in the parameter list so callers can omit values they do not need to override.

CSS

/* Mixin with parameters and defaults */
@mixin --button(--bg: #6c5ce7, --color: white, --radius: 8px) {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  padding: 0.6rem 1.4rem;
  background: var(--bg);
  color: var(--color);
  border: none;
  border-radius: var(--radius);
  font-weight: 600;
  font-size: 0.95rem;
  cursor: pointer;
  transition: filter 0.2s ease, transform 0.2s ease;
}

/* Mixin with a required parameter (no default) */
@mixin --gradient-text(--from, --to) {
  background: linear-gradient(135deg, var(--from), var(--to));
  -webkit-background-clip: text;
  -webkit-text-fill-color: transparent;
  background-clip: text;
}
Naming Convention: Mixin names must start with two dashes (--) just like custom properties. This keeps them in the same namespace and avoids collisions with future CSS keywords. Use descriptive, lowercase, hyphen-separated names: --card-surface, --flex-center, --sr-only.

2. Using Mixins with @apply

Once you have defined a mixin, you apply it inside any rule with @apply. The mixin's declarations get stamped directly into the rule as if you had written them by hand. Pass arguments to override defaults.

Basic Application

CSS

/* Apply a mixin with no arguments (uses all defaults) */
.btn-primary {
  @apply --button;
}

/* Apply a mixin with arguments */
.btn-danger {
  @apply --button(--bg: #ff7675, --color: white, --radius: 6px);
}

/* Only override what you need */
.btn-rounded {
  @apply --button(--radius: 999px);
}

/* Apply the visually-hidden mixin */
.sr-only {
  @apply --visually-hidden;
}

Resulting CSS

When the browser processes @apply --button(--radius: 999px);, it resolves to the full declaration block with the overridden radius. The output is equivalent to writing every property by hand:

CSS (resolved)

/* What .btn-rounded actually computes to */
.btn-rounded {
  display: inline-flex;
  align-items: center;
  justify-content: center;
  padding: 0.6rem 1.4rem;
  background: #6c5ce7;     /* default --bg */
  color: white;             /* default --color */
  border: none;
  border-radius: 999px;     /* overridden --radius */
  font-weight: 600;
  font-size: 0.95rem;
  cursor: pointer;
  transition: filter 0.2s ease, transform 0.2s ease;
}

Demo: Button Variants from One Mixin

All four buttons share the same --button mixin. Only the arguments differ, producing distinct visual variants from a single definition.

@apply --button; --bg: #ff7675 --bg: transparent --radius: 999px
Key Insight: @apply is not inheritance and not a class. It physically stamps declarations into the rule at author time. The mixin's declarations participate in the cascade exactly where @apply appears. This means specificity is determined by the rule that contains @apply, not by the mixin definition.

3. Composing Mixins

Mixins can call other mixins. This lets you build a layered design system where high-level components compose low-level primitives. A card mixin might compose a surface mixin and a spacing mixin. A hero section mixin might compose a gradient-text mixin with a layout mixin.

Composition Pattern

CSS

/* Low-level primitives */
@mixin --flex-center {
  display: flex;
  align-items: center;
  justify-content: center;
}

@mixin --surface(--bg: #1a1d27, --border-clr: #2e3345) {
  background: var(--bg);
  border: 1px solid var(--border-clr);
  border-radius: 12px;
}

@mixin --spacing(--px: 1.5rem, --py: 1.5rem) {
  padding: var(--py) var(--px);
}

/* High-level component composing primitives */
@mixin --card {
  @apply --surface;
  @apply --spacing;
  box-shadow: 0 4px 24px rgba(0, 0, 0, 0.25);
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}

@mixin --card-interactive {
  @apply --card;
  cursor: pointer;
}

/* Usage */
.feature-card {
  @apply --card-interactive;
}

.feature-card:hover {
  transform: translateY(-4px);
  box-shadow: 0 12px 40px rgba(0, 0, 0, 0.4);
}

Design System Architecture

A well-structured mixin system has three layers:

Primitives
--flex-center --surface --spacing --text-truncate --sr-only

Single-purpose utility blocks. Never compose other mixins.

▼
Patterns
--card --button --input-field --badge

Compose 2-3 primitives into reusable UI patterns.

▼
Components
--feature-card --nav-button --modal-surface

Compose patterns into specific, project-level components.

4. Practical Patterns

Mixins shine in real-world scenarios where you need consistent styles applied across many selectors. Here are the patterns that come up most often.

Responsive Mixins

Wrap media-query-aware declarations in a mixin so breakpoint logic stays centralized. When you change a breakpoint, every consumer updates automatically.

CSS

/* A responsive container mixin */
@mixin --responsive-grid(--cols-sm: 1, --cols-md: 2, --cols-lg: 3, --gap: 1.5rem) {
  display: grid;
  gap: var(--gap);
  grid-template-columns: repeat(var(--cols-sm), 1fr);

  @media (min-width: 768px) {
    grid-template-columns: repeat(var(--cols-md), 1fr);
  }

  @media (min-width: 1024px) {
    grid-template-columns: repeat(var(--cols-lg), 1fr);
  }
}

/* Usage */
.product-grid {
  @apply --responsive-grid(--cols-sm: 1, --cols-md: 2, --cols-lg: 4);
}

.blog-grid {
  @apply --responsive-grid(--cols-lg: 3, --gap: 2rem);
}

Theme Mixins

Define theme-aware surfaces that automatically adapt to light and dark modes. The mixin encapsulates both variants.

CSS

/* Theme-aware surface mixin */
@mixin --themed-surface(--light-bg: #ffffff, --dark-bg: #1a1d27) {
  background: light-dark(var(--light-bg), var(--dark-bg));
  color: light-dark(#1a1a2e, #e4e6ef);
  border: 1px solid light-dark(#e2e8f0, #2e3345);
  border-radius: 12px;
}

/* Theme-aware text mixin */
@mixin --themed-text(--light-clr: #1a1a2e, --dark-clr: #e4e6ef) {
  color: light-dark(var(--light-clr), var(--dark-clr));
}

.card {
  @apply --themed-surface;
  @apply --spacing(--px: 1.5rem, --py: 1.5rem);
}

.card-title {
  @apply --themed-text(--light-clr: #0f172a, --dark-clr: #f1f5f9);
  font-weight: 700;
}

Utility Mixins

Small, single-purpose mixins that solve recurring problems.

CSS

/* Text truncation with line clamping */
@mixin --line-clamp(--lines: 2) {
  display: -webkit-box;
  -webkit-line-clamp: var(--lines);
  -webkit-box-orient: vertical;
  overflow: hidden;
}

/* Aspect ratio container */
@mixin --aspect(--ratio: 16 / 9) {
  aspect-ratio: var(--ratio);
  overflow: hidden;
  object-fit: cover;
}

/* Focus ring for accessibility */
@mixin --focus-ring(--color: #6c5ce7, --offset: 2px) {
  outline: 2px solid var(--color);
  outline-offset: var(--offset);
}

/* Usage */
.card-desc {
  @apply --line-clamp(--lines: 3);
}

.thumbnail {
  @apply --aspect(--ratio: 4 / 3);
  border-radius: 8px;
}

.interactive:focus-visible {
  @apply --focus-ring;
}

5. Mixins vs @function

CSS now has both @mixin (stamps declarations) and @function (returns a single value). They solve different problems and are not interchangeable. Understanding the distinction is critical for writing clean CSS architecture.

The Core Difference

CSS

/* @function returns a VALUE — use in property values */
@function --spacing(--n) {
  result: calc(var(--n) * 0.25rem);
}

.card {
  padding: --spacing(6);          /* returns 1.5rem */
  margin-bottom: --spacing(8);    /* returns 2rem */
}

/* @mixin applies DECLARATIONS — stamps into a rule */
@mixin --card-base {
  background: #1a1d27;
  border: 1px solid #2e3345;
  border-radius: 12px;
  padding: 1.5rem;
}

.card {
  @apply --card-base;  /* stamps 4 declarations */
}

Using Both Together

The real power comes from combining them. Functions compute values, mixins stamp declarations that use those values.

CSS

/* Function for the spacing scale */
@function --sp(--n) {
  result: calc(var(--n) * 0.25rem);
}

/* Function for brand colors */
@function --brand(--lightness) {
  result: oklch(var(--lightness) 0.18 265);
}

/* Mixin uses both functions */
@mixin --card(--size: medium) {
  background: --brand(0.15);
  border: 1px solid --brand(0.25);
  border-radius: --sp(3);
  padding: if(
    style(--size: small):  --sp(3) --sp(4);
    style(--size: large):  --sp(8) --sp(10);
    else:                  --sp(6) --sp(8)
  );
}

.card-sm { @apply --card(--size: small); }
.card    { @apply --card; }
.card-lg { @apply --card(--size: large); }
Rule of Thumb: If you need a value to plug into a property, write a @function. If you need a set of declarations to stamp into a rule, write a @mixin. If you catch yourself writing a mixin with a single declaration, it probably should be a function instead.

6. Progressive Enhancement

CSS @mixin is a cutting-edge feature. Not all browsers support it yet, so you need a progressive enhancement strategy. The good news: @supports can detect mixin support, and the fallback patterns are straightforward.

Detecting @mixin Support

CSS

/* Feature detection for @mixin / @apply */
@supports (--mixin: @apply --test) {
  /* Mixin-powered styles go here */
  .card {
    @apply --card-surface;
  }
}

/* Alternative: detect via the at-rule itself */
@supports at-rule(@mixin) {
  /* Browser understands @mixin syntax */
  @mixin --elevated {
    box-shadow: 0 8px 32px rgba(0, 0, 0, 0.3);
  }

  .floating-panel {
    @apply --elevated;
  }
}

Fallback Strategy

Write your baseline styles without mixins. Then layer mixin-powered enhancements on top inside @supports. Browsers that do not understand @mixin skip the block entirely and get the baseline.

CSS

/* 1. Baseline: works everywhere */
.btn {
  display: inline-flex;
  align-items: center;
  padding: 0.6rem 1.4rem;
  background: #6c5ce7;
  color: white;
  border: none;
  border-radius: 8px;
  font-weight: 600;
  cursor: pointer;
}

/* 2. Enhanced: when @mixin is supported */
@supports at-rule(@mixin) {
  @mixin --button(--bg: #6c5ce7, --radius: 8px) {
    display: inline-flex;
    align-items: center;
    padding: 0.6rem 1.4rem;
    background: var(--bg);
    color: white;
    border: none;
    border-radius: var(--radius);
    font-weight: 600;
    cursor: pointer;
    transition: filter 0.2s, transform 0.2s;
  }

  .btn         { @apply --button; }
  .btn-danger  { @apply --button(--bg: #ff7675); }
  .btn-pill    { @apply --button(--radius: 999px); }
}

Exercise: Build a Component Library with Mixins

Create a mini component library using @mixin and @apply. You will define primitive mixins, compose them into component mixins, then use them to style a set of UI elements.

Requirements

  • Define a --surface mixin with parameters for --bg, --border-clr, and --radius with sensible defaults.
  • Define a --flex-center mixin that centers content both axes.
  • Define a --button mixin that composes --flex-center and accepts --bg, --color, and --radius.
  • Create at least 3 button variants: primary, secondary, and destructive.
  • Define a --card mixin that composes --surface and adds shadow + transition.
  • Create 2 card variants: default and elevated.
  • Add :hover styles for buttons (darken background) and cards (lift with shadow).
  • Wrap mixin-dependent styles in @supports at-rule(@mixin) with a baseline fallback outside.

Challenge: Mixin-Powered Design System

Build a complete design system dashboard using CSS mixins for every component. The dashboard should demonstrate a real-world architecture where primitives compose into patterns, and patterns compose into components.

Requirements

  • Primitive Mixins: Create --surface, --flex-center, --spacing, --text-truncate, and --focus-ring primitives.
  • Pattern Mixins: Compose primitives into --card, --button, --input-field, and --badge patterns.
  • Dashboard Layout: A header with navigation buttons, a stats row with 4 metric cards, and a content area with a sidebar.
  • Theme Support: Use a --themed-surface mixin with light-dark() for automatic light/dark mode switching.
  • Responsive Grid: Use a --responsive-grid mixin for the stats row (4 cols desktop, 2 cols tablet, 1 col mobile).
  • Functions + Mixins: Use a @function --sp() for spacing values inside your mixins.
  • Progressive Enhancement: Wrap all mixin usage in @supports with complete baseline fallbacks.
  • Interactive Elements: All buttons and cards should have hover/focus states using mixin-applied transitions.

Architecture Hints

  • Define all primitives first, then patterns, then apply them. This keeps the dependency tree clean.
  • For the responsive grid, nest @media rules inside the mixin body.
  • Use @layer primitives, patterns, components; to organize your mixin definitions by abstraction level.
  • Test your baseline styles by temporarily removing the @supports block.
