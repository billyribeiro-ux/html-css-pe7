CSS Math Functions

Go beyond calc() and clamp(). Master rounding, sign detection, trigonometry, exponentials, and stepped values to build circular layouts, wave patterns, grid-snapped spacing, and physics-informed animations — entirely in CSS.

1. Rounding Functions

CSS rounding functions give you precise control over numeric snapping. Before these existed, fractional pixel values and sub-pixel rendering bugs were a constant source of layout headaches. With round(), mod(), and rem(), you can snap values to a grid, enforce pixel-perfect alignment, and build design token systems that stay perfectly consistent.

round()

The round() function rounds a value to the nearest multiple of an interval. It accepts an optional rounding strategy as the first argument.

CSS

/* Syntax: round(strategy, value, interval) */

/* Round to nearest 0.25rem (quarter-rem grid) */
.element {
  padding: round(nearest, 1.37rem, 0.25rem);  /* = 1.25rem */
}

/* Always round up */
.min-height {
  min-height: round(up, 4.2rem, 1rem);  /* = 5rem */
}

/* Always round down */
.container {
  width: round(down, 95.7%, 5%);  /* = 95% */
}

/* Round to zero (truncate toward zero) */
.truncated {
  margin: round(to-zero, -1.8rem, 1rem);  /* = -1rem */
}
Key Insight: The four rounding strategies are nearest (default, rounds to closest), up (always toward positive infinity), down (always toward negative infinity), and to-zero (truncates the fractional part toward zero). When no strategy is specified, nearest is used.

mod() and rem()

Both mod() and rem() compute the remainder of a division, but they differ in how they handle negative numbers. mod() uses floored division (result takes the sign of the divisor), while rem() uses truncated division (result takes the sign of the dividend).

CSS

/* mod(a, b) - floored remainder, takes sign of b */
.element {
  /* Cycle through 0, 1, 2, 3, 0, 1, 2, 3... */
  --cycle: mod(var(--index), 4);
}

/* rem(a, b) - truncated remainder, takes sign of a */
.offset {
  /* Stays within bounds */
  left: rem(var(--scroll-pos), 100px);
}

/* Practical: zebra stripe via mod */
.row {
  --stripe: mod(var(--row-index), 2);
  background: color-mix(
    in oklch,
    var(--bg-alt) calc(var(--stripe) * 100%),
    var(--bg-base)
  );
}

2. Sign & Absolute Value

Two deceptively simple functions that unlock powerful patterns: abs() returns the magnitude of a value (always positive), and sign() returns its direction (-1, 0, or 1). Together, they let you build directional offsets, always-positive spacing, and conditional layout logic that reacts to custom property values.

abs()

CSS

/* Always-positive distance from center */
.item {
  --offset: calc(var(--index) - var(--center));
  /* abs() guarantees a positive result */
  opacity: calc(1 - abs(var(--offset)) * 0.15);
  scale: calc(1 - abs(var(--offset)) * 0.05);
}

/* Ensuring positive margins regardless of input */
.spaced {
  margin-block: abs(var(--spacing));
}

sign()

CSS

/* Returns -1, 0, or 1 */
.directional {
  --dir: sign(var(--velocity));

  /* Flip an arrow icon based on direction */
  transform: scaleX(sign(var(--velocity)));

  /* Apply offset only in the direction of movement */
  translate: calc(sign(var(--dx)) * 10px) 0;
}

/* Conditional shadow direction */
.card {
  --tilt: -15;
  box-shadow:
    calc(sign(var(--tilt)) * 8px) 4px 20px rgba(0, 0, 0, 0.3);
}

3. Stepped Values & Design Tokens

One of the most practical applications of round() is building stepped value systems. By rounding arbitrary input values to a fixed interval, you can enforce consistent spacing, sizing, and alignment across an entire design system — even when values are computed dynamically.

Quarter-Rem Spacing Grid

CSS

:root {
  --space-unit: 0.25rem;  /* 4px base unit */
}

/* Any computed spacing snaps to the 4px grid */
.component {
  /* 1.37rem snaps to 1.25rem (5 * 0.25rem) */
  padding: round(nearest, 1.37rem, var(--space-unit));

  /* 0.83rem snaps to 0.75rem (3 * 0.25rem) */
  gap: round(nearest, 0.83rem, var(--space-unit));

  /* Dynamic spacing that always stays on grid */
  margin-block: round(nearest, calc(2vw + 0.5rem), var(--space-unit));
}

Font Size Stepping

CSS

/* Fluid type that snaps to readable sizes */
.heading {
  font-size: round(
    nearest,
    clamp(1.25rem, 2vw + 1rem, 2.5rem),
    0.125rem  /* snap to 2px increments */
  );
}

/* Modular scale with rounding */
:root {
  --ratio: 1.25;
  --step-0: 1rem;
  --step-1: round(nearest, calc(var(--step-0) * var(--ratio)), 0.125rem);
  --step-2: round(nearest, calc(var(--step-1) * var(--ratio)), 0.125rem);
  --step-3: round(nearest, calc(var(--step-2) * var(--ratio)), 0.125rem);
}

This is how professional design systems maintain visual consistency at every breakpoint.

4. Predictable Fluid Sizing: round() Meets clamp()

In the spirit of Ahmad Shadeed's visual CSS explorations, let us take a step back and study a problem that clamp() alone cannot solve. Fluid typography with clamp() is wonderful — text grows smoothly between a minimum and a maximum as the viewport changes. But smooth also means continuous, and continuous means unpredictable. At 1024px your heading might compute to 31.18px; at 1025px it becomes 31.21px. Every intermediate viewport produces a slightly different, sub-pixel, never-quite-round number. Your carefully designed type scale dissolves into an infinite gradient of values.

The now well-supported round() function fixes this. By wrapping a fluid expression in round(), you keep the responsiveness of clamp() while snapping every computed result onto a clean, predictable grid. The text still grows with the viewport — it just does so in deliberate steps you control, instead of an unbounded smear of fractional pixels.

The core idea: clamp() answers "how big, between these bounds?" — round() answers "snapped to which step?". Composing them, round(clamp(...), step), gives you fluid sizing that is also rhythmic and reproducible. This is the foundation of a type scale that looks intentional at every width, not just at your breakpoints.

The Problem with Raw clamp()

CSS

/* Smooth, but every viewport yields a different
   sub-pixel value: 31.18px, 31.21px, 31.24px... */
.heading {
  font-size: clamp(1.5rem, 1rem + 2.5vw, 2.5rem);
}

Snapping the Fluid Result with round()

Wrap the whole clamp() expression in round() and pick a snapping interval. A 0.125rem (2px) grid keeps things fluid-feeling; a 0.5rem grid produces visibly discrete jumps.

CSS

/* Still fluid, but every result lands on a 2px grid */
.heading {
  font-size: round(
    clamp(1.5rem, 1rem + 2.5vw, 2.5rem),
    0.125rem
  );
}

/* "Stepped fluid": the size visibly jumps in 0.5rem
   increments as the viewport grows — no in-between values */
.display {
  font-size: round(
    up,
    clamp(2rem, 1rem + 4vw, 4rem),
    0.5rem
  );
}
Key Insight: round() takes an optional strategy as its first argument, exactly as in Section 1. round(nearest, ...) keeps the value closest to the fluid curve, while round(up, ...) guarantees the text never dips below a step — useful when you want to protect a minimum legible size at any viewport. The interval is what decides how "steppy" versus "smooth" the fluidity feels.

A Cleaner Modular Type Scale

Modular scales multiply a base size by a ratio for each step (Section 5 covers pow() in depth). The trouble is that 1rem × 1.25³ equals 1.953125rem — an ugly, hard-to-reason-about number. Snapping each step with round() produces a scale that is both fluid (because the base is fluid) and clean (because every step is rounded to a shared grid).

CSS

:root {
  /* A fluid base size drives the entire scale */
  --base: clamp(1rem, 0.9rem + 0.4vw, 1.15rem);
  --ratio: 1.25;
  --snap: 0.125rem;  /* shared 2px grid */
}

/* Each step is fluid AND snapped to the grid */
.text-0 { font-size: round(var(--base), var(--snap)); }
.text-1 { font-size: round(calc(var(--base) * pow(var(--ratio), 1)), var(--snap)); }
.text-2 { font-size: round(calc(var(--base) * pow(var(--ratio), 2)), var(--snap)); }
.text-3 { font-size: round(calc(var(--base) * pow(var(--ratio), 3)), var(--snap)); }
.text-4 { font-size: round(calc(var(--base) * pow(var(--ratio), 4)), var(--snap)); }

Refined Responsive Layouts

The same technique refines layout, not just type. Fluid gaps, paddings, and column widths computed from viewport units rarely land on your spacing grid. Snapping them with round() keeps an entire responsive layout aligned to a single baseline rhythm — no matter how the viewport flexes.

CSS

:root {
  --grid-unit: 0.5rem;  /* 8px baseline rhythm */
}

.layout {
  /* Fluid gap that always lands on the 8px baseline */
  gap: round(clamp(1rem, 2vw, 2rem), var(--grid-unit));

  /* Fluid padding snapped to the same rhythm */
  padding-block: round(up, clamp(1.5rem, 4vw, 4rem), var(--grid-unit));
}

/* Fluid columns that snap to whole, predictable widths */
.card {
  inline-size: round(clamp(16rem, 30vw, 24rem), 1rem);
}
Browser support: round() is now well supported across every modern engine — Chrome 125+, Safari 15.4+, and Firefox 118+ — so pairing it with clamp() is production-ready today. For ancient browsers, the value simply falls back to the unrounded clamp() expression inside an @supports (width: round(1px, 1px)) guard, which degrades gracefully to plain fluid sizing.

5. Trigonometric Functions

This is where CSS math gets genuinely exciting. The trigonometric functions sin(), cos(), tan(), and their inverses asin(), acos(), atan(), atan2() are fully supported in all major browsers since 2024. They unlock circular layouts, wave patterns, orbital animations, clock faces, and spiral arrangements — all in pure CSS.

The Core Functions

CSS

/* sin() and cos() accept angles directly */
.item {
  /* Position on a circle of radius 150px */
  --angle: calc(var(--i) * (360deg / var(--total)));
  --x: calc(cos(var(--angle)) * 150px);
  --y: calc(sin(var(--angle)) * 150px);
  transform: translate(var(--x), var(--y));
}

/* tan() for skew calculations */
.skewed {
  /* Calculate skew offset from an angle */
  --offset: calc(tan(15deg) * 100px);
}

/* Inverse functions return angles */
.arrow {
  /* atan2(y, x) gives the angle toward a point */
  rotate: atan2(var(--dy), var(--dx));
}

/* Using radians explicitly */
.wave {
  --phase: calc(var(--i) * 0.5);  /* unitless = radians */
  translate: 0 calc(sin(var(--phase)) * 20px);
}
Key Insight: CSS trig functions accept both degrees (sin(45deg)) and radians (sin(0.785)). A unitless number is treated as radians. For most layout work, degrees are more intuitive: divide 360deg by the number of items to space them evenly around a circle.

Circular Layout Pattern

The canonical use case for CSS trig: placing items in a circle. Each item's position is computed from its index and the total count. No JavaScript, no hardcoded positions.

CSS

.circular-container {
  --radius: 140px;
  --total: 8;
  position: relative;
  width: calc(var(--radius) * 2 + 60px);
  height: calc(var(--radius) * 2 + 60px);
}

.circular-item {
  --angle: calc(var(--i) * (360deg / var(--total)));
  position: absolute;
  top: 50%;
  left: 50%;
  transform: translate(-50%, -50%)
    translate(
      calc(cos(var(--angle)) * var(--radius)),
      calc(sin(var(--angle)) * var(--radius))
    );
}

6. Exponential Functions

The exponential family — pow(), sqrt(), hypot(), log(), and exp() — opens the door to non-linear progressions, distance calculations, easing curves, and logarithmic scales. These are the tools you reach for when linear interpolation is not enough.

pow() and sqrt()

CSS

/* pow(base, exponent) - raise to a power */
.scale {
  /* Quadratic easing: fast start, slow end */
  --progress: 0.5;
  --eased: pow(var(--progress), 2);  /* 0.25 */
  translate: calc(var(--eased) * 200px) 0;
}

/* sqrt(value) - square root */
.responsive {
  /* Square root scaling: grows fast then slows */
  font-size: calc(sqrt(var(--container-w)) * 0.1rem);
}

/* Modular type scale using pow() */
:root {
  --ratio: 1.25;
  --size-0: 1rem;
  --size-1: calc(var(--size-0) * pow(var(--ratio), 1));  /* 1.25rem */
  --size-2: calc(var(--size-0) * pow(var(--ratio), 2));  /* 1.5625rem */
  --size-3: calc(var(--size-0) * pow(var(--ratio), 3));  /* 1.953rem */
}

hypot() — Distance Calculation

CSS

/* hypot(a, b) = sqrt(a*a + b*b) - Pythagorean distance */
.diagonal {
  /* Calculate the diagonal of a box */
  --w: 300px;
  --h: 200px;
  --diagonal: hypot(var(--w), var(--h));  /* ~360.56px */

  /* Useful for sizing an overlay that covers corners */
  background-size: var(--diagonal) var(--diagonal);
}

/* Distance between two points */
.connector {
  --dx: calc(var(--x2) - var(--x1));
  --dy: calc(var(--y2) - var(--y1));
  width: hypot(var(--dx), var(--dy));
  rotate: atan2(var(--dy), var(--dx));
}

log() and exp()

CSS

/* log(value) - natural logarithm */
/* exp(value) - e raised to the power */

/* Logarithmic scale for audio-style sliders */
.volume-slider {
  --linear: 0.5;
  --log-scale: calc(log(var(--linear) * 9 + 1) / log(10));
  width: calc(var(--log-scale) * 100%);
}

/* Exponential growth for animation timing */
.cascade {
  --delay: calc(exp(var(--i) * 0.3) * 50ms);
  animation-delay: var(--delay);
}

7. Practical Patterns

Now that you have the full toolkit, let us see how these functions combine in real-world patterns. These are not academic exercises — these are patterns you will use in production to solve problems that previously required JavaScript.

Pattern 1: Orbital Animation

Items orbit a central point using sin() and cos() combined with CSS animations. The animation simply increments an angle custom property, and the trig functions handle the positioning.

CSS

@property --orbit-angle {
  syntax: "<angle>";
  initial-value: 0deg;
  inherits: false;
}

.orbiter {
  --orbit-angle: 0deg;
  --radius: 100px;
  translate:
    calc(cos(var(--orbit-angle)) * var(--radius))
    calc(sin(var(--orbit-angle)) * var(--radius));
  animation: orbit 4s linear infinite;
}

@keyframes orbit {
  to { --orbit-angle: 360deg; }
}

Pattern 2: Star Rating with round()

Snap arbitrary decimal ratings to the nearest half-star using round(). The fill width is precisely controlled without JavaScript rounding logic.

CSS

.star-rating {
  --raw-rating: 3.7;
  /* Snap to nearest 0.5 */
  --rating: round(nearest, var(--raw-rating), 0.5);
  /* = 3.5 */

  /* Fill width based on 5-star scale */
  --fill: calc(var(--rating) / 5 * 100%);
}

.star-rating::after {
  content: "";
  width: var(--fill);
  background: gold;
}

Pattern 3: Responsive Aspect Ratios with sqrt()

CSS

/* Dynamic aspect ratio that smoothly transitions
   between portrait and landscape */
.adaptive-card {
  --w: 300;
  --h: 200;
  /* Use hypot to get the diagonal for scaling */
  --diagonal: hypot(var(--w), var(--h));
  /* Use atan2 for the angle of the diagonal */
  --angle: atan2(var(--h), var(--w));

  aspect-ratio: var(--w) / var(--h);
  max-width: calc(var(--diagonal) * 1px);
}
Key Insight: The combination of atan2() and hypot() gives you the full polar coordinate conversion: distance and angle from the origin. This is the foundation for drawing connectors between elements, rotating arrows to point at targets, and computing dynamic layout angles — all without JavaScript.

  .circular-nav {
    /* Use sin()/cos() layout */
  }

  /* Fallback: hardcoded position */

  --y: 0px;

  }

Create a circular navigation menu using CSS trigonometric functions. Items should be evenly distributed around a circle, with smooth hover effects and responsive sizing.

Requirements

Challenge: Animated Wave Background

Build an animated wave section divider using CSS trigonometric functions. The wave should undulate smoothly, use multiple layers for depth, and adapt to the container width.

Requirements

  • Wave dots: Create at least 20 dots per wave row. Each dot's vertical position should be calc(sin(var(--i) * 18deg + var(--phase)) * var(--amplitude)) where --phase is animated.
  • Multiple layers: Stack 2-3 wave rows with different --amplitude values and phase offsets to create depth.
  • Animation: Use @property to register --phase as an <angle> and animate it from 0deg to 360deg.
  • Color coding: Use the dot's index with mod() to cycle through a color palette, or shift the hue using calc(var(--i) * 18) in OKLCH.
  • Responsive: Dots should spread evenly using flexbox or grid. The amplitude should scale with viewport width using clamp().
  • Snapped sizes: Use round() to snap dot sizes to a 2px grid for crisp rendering.

Architecture Hints

  • Register @property --phase with syntax: "<angle>" so CSS can interpolate it in keyframes.
  • Use translate: 0 calc(sin(var(--i) * 18deg + var(--phase)) * var(--amp)) on each dot.
  • Layer multiple rows using absolute positioning and different --amp / animation-duration values.
  • Add opacity: calc(0.3 + abs(sin(var(--i) * 18deg + var(--phase))) * 0.7) for pulsing transparency.
  • Use scale: round(nearest, calc(0.5 + abs(sin(var(--i) * 18deg)) * 0.8), 0.1) for stepped sizing.
