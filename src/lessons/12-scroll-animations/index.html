Scroll-Powered Experiences

Harness scroll-driven animations, scroll snap, CSS-only carousels, and parallax effects to build immersive, performant pages — all without a single line of JavaScript.

1. Why Scroll-Driven Animations

Traditionally, creating animations tied to the user's scroll position required JavaScript — attaching a scroll event listener, reading scrollTop, and manually calculating how far through the page the user had scrolled. This approach has serious problems: the scroll event fires on the main thread (often dozens of times per second), each handler invocation triggers style recalculation and potential layout thrashing, and the animation jitters because the browser cannot guarantee when your JavaScript will run relative to the next paint.

CSS Scroll-Driven Animations solve all of these problems by moving the entire animation pipeline off the main thread. You declare an animation using standard @keyframes, then bind it to scroll progress instead of time using the animation-timeline property. The browser's compositor thread handles the interpolation, which means your animations run at a smooth 60fps even while the main thread is busy executing JavaScript, fetching data, or rendering other content.

There are two fundamental types of scroll-driven timelines. A scroll progress timeline (scroll()) tracks how far a scroll container has been scrolled — from 0% at the top to 100% at the bottom. A view progress timeline (view()) tracks an element's visibility within a scroll container — from 0% when it first enters the viewport to 100% when it fully exits. Together these two primitives can express virtually any scroll-based interaction.

Why This Matters: JavaScript scroll listeners block the main thread, cause jank under load, and require manual cleanup to avoid memory leaks. CSS scroll-driven animations run on the compositor thread, are automatically garbage-collected, respect prefers-reduced-motion, and are declarative — making them easier to write, debug, and maintain.

2. animation-timeline: scroll()

The scroll() function creates a scroll progress timeline that maps an element's scroll position to animation progress. When the container is at the top (or left, for horizontal scrolling), the animation is at 0%. When the container is fully scrolled to the bottom (or right), the animation reaches 100%. You attach this timeline to any standard CSS animation using animation-timeline: scroll().

The scroll() function accepts two optional arguments: a scroller and an axis. The scroller can be nearest (default — the nearest ancestor scroll container), root (the document viewport), or self (the element itself if it scrolls). The axis can be block (default), inline, x, or y. For a standard vertical page scroll progress bar, scroll(root) is the most common choice.

Because scroll-driven animations use standard @keyframes, you can animate any CSS property that is normally animatable — transforms, opacity, colors, clip-path, and even custom properties registered with @property. The key difference from time-based animations is that you typically omit animation-duration (or set it to auto) since the scroll position, not elapsed time, controls progress.

/* A progress bar that fills as the page scrolls */
.scroll-progress {
  position: fixed;
  top: 0;
  left: 0;
  height: 4px;
  width: 100%;
  background: #6366f1;
  transform-origin: left;
  animation: progress-fill linear;
  animation-timeline: scroll(root);
}

@keyframes progress-fill {
  from { transform: scaleX(0); }
  to   { transform: scaleX(1); }
}

/* scroll() arguments: scroller, axis */
.horizontal-indicator {
  animation: slide-across linear;
  animation-timeline: scroll(nearest inline);
}

/* Self-scrolling container */
.self-scroll-demo {
  overflow-y: scroll;
  animation: fade-bg linear;
  animation-timeline: scroll(self block);
}

@keyframes fade-bg {
  from { background: #1e293b; }
  to   { background: #6366f1; }
}

3. animation-timeline: view()

While scroll() tracks how far a container has scrolled, view() tracks how far an individual element has progressed through its scroll container's visible area (the "scrollport"). This is the CSS equivalent of an Intersection Observer, but with the animation running on the compositor thread instead of firing JavaScript callbacks.

When an element first enters the scrollport from the bottom, its view progress is 0%. As it scrolls further into view, the progress increases. When it is fully visible and centered, it is around 50%. When it scrolls out the top, it reaches 100%. This makes view() perfect for "reveal on scroll" animations — fade-ins, slide-ups, scale effects, and progressive content disclosure.

The view() function accepts an axis argument (block or inline) and an optional inset that adjusts when the animation starts and ends relative to the scrollport edges. For example, view(block 20% 20%) starts the animation when the element is 20% inside the viewport edge and ends it 20% before the opposite edge, effectively shrinking the active zone.

/* Cards fade and slide in when scrolling into view */
.reveal-card {
  animation: reveal linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}

@keyframes reveal {
  from {
    opacity: 0;
    transform: translateY(60px) scale(0.95);
  }
  to {
    opacity: 1;
    transform: translateY(0) scale(1);
  }
}

/* Using view() with inset to start animation earlier */
.early-reveal {
  animation: fade-in linear both;
  animation-timeline: view(block 100px 0px);
}

4. animation-range

The animation-range property gives you fine-grained control over which portion of the scroll or view timeline drives your animation. Without it, the animation maps to the full 0%–100% of the timeline. With animation-range, you can restrict the animation to only a subset — for example, only the "entry" phase when an element is first scrolling into view, or only the "exit" phase when it is scrolling out.

For view timelines, there are four named range keywords: entry (the element is entering the scrollport), exit (it is leaving), contain (it is fully contained within the scrollport), and cover (the full range from first pixel entering to last pixel leaving — which is the default). Each keyword can be followed by a percentage to target a sub-range within that phase.

You can combine two range points to define a custom span. For example, animation-range: entry 0% cover 50% runs the animation from the moment the element starts entering until it is 50% through the full cover range. This level of control enables staggered, multi-phase animations — one animation for entry, another for the contained phase, and a third for exit.

/* Only animate during entry (element scrolling into view) */
.entry-only {
  animation: slide-up linear both;
  animation-timeline: view();
  animation-range: entry 0% entry 100%;
}

/* Only animate during exit (element scrolling out of view) */
.exit-only {
  animation: fade-out linear both;
  animation-timeline: view();
  animation-range: exit 0% exit 100%;
}

/* Animate while element is fully contained in viewport */
.contain-phase {
  animation: glow linear both;
  animation-timeline: view();
  animation-range: contain 0% contain 100%;
}

/* Full cover range (default behavior) */
.full-cover {
  animation: scale-rotate linear both;
  animation-timeline: view();
  animation-range: cover 0% cover 100%;
}

5. Scroll Snap

CSS Scroll Snap provides native, smooth snapping behavior for scrollable containers. When a user finishes a scroll gesture, the browser automatically snaps to a defined alignment point rather than stopping at an arbitrary position. This eliminates the need for JavaScript-based scroll snapping libraries and produces a smoother, more responsive result because the browser's scroll physics engine handles the deceleration and snap animation natively.

The parent scroll container uses scroll-snap-type to enable snapping. This property takes two values: an axis (x, y, block, inline, or both) and a strictness (mandatory or proximity). With mandatory, the scroll container always snaps to a snap point after scrolling. With proximity, it only snaps when the scroll position is near a snap point, allowing free scrolling in between.

Each child element that should act as a snap target uses scroll-snap-align to declare where it should align within the scrollport. Values include start, center, and end. The parent can also use scroll-padding to create an offset from the container edge, which is essential when you have a fixed header or navigation bar that would otherwise overlap snapped content.

/* Parent: enable horizontal snapping */
.image-gallery {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-padding: 1rem;
  gap: 1rem;
  -webkit-overflow-scrolling: touch;
}

/* Children: snap to center */
.gallery-slide {
  flex: 0 0 80%;
  scroll-snap-align: center;
  border-radius: 12px;
}

/* Vertical snapping for full-page sections */
.fullpage-container {
  overflow-y: auto;
  scroll-snap-type: y mandatory;
  height: 100vh;
}

.fullpage-section {
  height: 100vh;
  scroll-snap-align: start;
}

6. ::scroll-button() — Native Carousel Buttons

The ::scroll-button() pseudo-element is a cutting-edge CSS feature that generates native navigation buttons for scroll containers. Instead of creating separate button elements and wiring up JavaScript click handlers to call scrollBy(), you can let the browser generate "previous" and "next" buttons automatically. These buttons scroll the container by one "page" (the width or height of the scrollport) in the specified direction.

The pseudo-element takes a direction keyword: ::scroll-button(left), ::scroll-button(right), ::scroll-button(up), or ::scroll-button(down). You can also use logical directions: inline-start, inline-end, block-start, block-end. The browser automatically disables the button (and applies the :disabled state) when there is no more content to scroll in that direction.

Because these are pseudo-elements, you style them with CSS just like ::before or ::after. You can set their content, positioning, colors, hover effects, and transitions. Combined with scroll snap, ::scroll-button() creates a fully functional carousel with zero JavaScript.

/* Generate prev/next buttons on a scroll container */
.carousel {
  overflow-x: auto;
  scroll-snap-type: x mandatory;
}

.carousel::scroll-button(left) {
  content: "\2039";  /* single left angle quote */
  position: absolute;
  left: 0.5rem;
  top: 50%;
  translate: 0 -50%;
  font-size: 2rem;
  background: rgba(0, 0, 0, 0.6);
  color: white;
  border-radius: 50%;
  width: 3rem;
  height: 3rem;
  display: grid;
  place-items: center;
  cursor: pointer;
}

.carousel::scroll-button(right) {
  content: "\203A";  /* single right angle quote */
  /* Same styling, positioned on right */
}

/* Auto-disabled when at scroll boundary */
.carousel::scroll-button(left):disabled {
  opacity: 0.3;
  cursor: default;
}

7. ::scroll-marker — Dot Indicators

The ::scroll-marker pseudo-element complements ::scroll-button() by generating position indicator dots (or any shape you style) for each snap target in a scroll container. These markers automatically reflect which item is currently snapped into view, and clicking a marker scrolls the container to the corresponding item. Think of them as the dot indicators at the bottom of a mobile carousel.

Each child element inside the scroll container can generate a marker using the ::scroll-marker pseudo-element. The parent scroll container uses the ::scroll-marker-group pseudo-element to create a container for all the markers, which you can position and style as a flex or grid layout. The browser automatically handles the "active" state — the marker corresponding to the currently visible snap target receives an active style.

Markers are interactive: clicking a marker smoothly scrolls the container to the associated element. Combined with scroll-snap-type, this creates a complete navigation system. The ::scroll-marker pseudo-element on each child defines its appearance, and you can use the :target-current pseudo-class to style the active marker differently.

/* Create a marker group container below the carousel */
.carousel::scroll-marker-group {
  display: flex;
  justify-content: center;
  gap: 0.5rem;
  padding: 1rem;
}

/* Each slide generates a dot marker */
.carousel-slide::scroll-marker {
  content: "";
  width: 12px;
  height: 12px;
  border-radius: 50%;
  background: rgba(255, 255, 255, 0.3);
  border: 2px solid rgba(255, 255, 255, 0.5);
  cursor: pointer;
  transition: all 0.3s ease;
}

/* Active marker (currently visible slide) */
.carousel-slide::scroll-marker:target-current {
  background: white;
  border-color: white;
  transform: scale(1.2);
}

8. Complete CSS-Only Carousel

Now we bring everything together: scroll snap for the sliding behavior, ::scroll-button() for prev/next navigation, and ::scroll-marker for position indicators. The result is a fully functional, accessible carousel component built entirely with CSS — no JavaScript, no external libraries, no ARIA hacks for custom controls.

The architecture is simple. The carousel container uses overflow-x: auto with scroll-snap-type: x mandatory. Each slide uses scroll-snap-align: center (or start). The ::scroll-button(left) and ::scroll-button(right) pseudo-elements provide arrow navigation. The ::scroll-marker-group pseudo-element on the container hosts the dot indicators, and each slide's ::scroll-marker pseudo-element defines a clickable dot.

This approach is a paradigm shift. Carousel components have traditionally been among the most complex UI patterns, requiring hundreds of lines of JavaScript for scrolling, snapping, button state management, active indicator tracking, touch handling, and keyboard navigation. The CSS-only version handles all of this natively, with better performance, full accessibility, and in roughly 50 lines of CSS.

/* Complete CSS-only carousel */
.full-carousel {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-behavior: smooth;
  position: relative;
}

/* Slides */
.full-carousel .slide {
  flex: 0 0 100%;
  scroll-snap-align: center;
}

/* Prev / Next buttons */
.full-carousel::scroll-button(left) {
  content: "\2039";
  /* ... positioning and styling */
}

.full-carousel::scroll-button(right) {
  content: "\203A";
  /* ... positioning and styling */
}

/* Dot indicator group */
.full-carousel::scroll-marker-group {
  display: flex;
  justify-content: center;
  gap: 0.5rem;
  padding-block: 1rem;
}

/* Individual dot indicators */
.full-carousel .slide::scroll-marker {
  content: "";
  width: 10px;
  height: 10px;
  border-radius: 50%;
  background: rgba(255,255,255,0.3);
}

.full-carousel .slide::scroll-marker:target-current {
  background: white;
}

9. Parallax with Scroll Timeline

Parallax scrolling — where background elements move at a different rate than foreground content — has traditionally required JavaScript to calculate offsets on every scroll event. With scroll-driven animations, you can achieve true parallax entirely in CSS by binding transform: translateY() animations to the scroll timeline at different rates for different layers.

The technique is straightforward: create multiple layers (background, midground, foreground) and give each a scroll-driven animation that translates it vertically, but with different keyframe values. The background layer moves slowly (small translate range), the midground moves at a medium rate, and the foreground moves at the normal scroll rate (or not at all). The visual result is a convincing depth effect.

You can also use animation-timeline: view() on individual elements to create localized parallax effects as sections scroll into view. This is perfect for hero sections, landing pages, and storytelling layouts where different elements — headings, images, decorative shapes — should move at different speeds relative to the viewport.

/* Parallax background using scroll timeline */
.parallax-section {
  position: relative;
  overflow: hidden;
  min-height: 60vh;
}

.parallax-bg {
  position: absolute;
  inset: -30% 0;
  background-image: url('mountains.jpg');
  background-size: cover;
  animation: parallax-shift linear;
  animation-timeline: view();
}

@keyframes parallax-shift {
  from { transform: translateY(-15%); }
  to   { transform: translateY(15%); }
}

/* Foreground content moves at normal rate */
.parallax-content {
  position: relative;
  z-index: 1;
}

10. Scroll-Triggered Animations & trigger-scope

Chrome 146+ introduces scroll-triggered animations with a new concept: trigger-scope. While scroll-driven animations bind animation progress to scroll position (the animation tracks where you are in the scroll), scroll-triggered animations fire an animation when a scroll condition is met — similar to how Intersection Observer triggers a callback, but declaratively in CSS.

The trigger-scope property limits the visibility of trigger names to a specific subtree of the DOM. This prevents trigger names from leaking out and accidentally activating animations in unrelated parts of the page. Think of it as scoping custom identifiers (like @keyframes names) to a specific container.

/* trigger-scope limits the visibility of trigger names */
.carousel {
  trigger-scope: --slide-trigger;
}

.carousel .slide {
  animation: fadeIn 0.5s;
  animation-trigger: --slide-trigger;
}

@keyframes fadeIn {
  from { opacity: 0; transform: translateY(20px); }
  to   { opacity: 1; transform: translateY(0); }
}

This pattern is especially powerful for component-based architectures. Each carousel, accordion, or tabbed interface can define its own trigger scope, ensuring that scroll-triggered animations within one component do not interfere with another. The trigger fires when the element enters the viewport (or a specified threshold), and the animation plays once rather than being continuously tied to scroll position.

Safari 26.4 Compositor Optimization: Safari 26.4 now runs scroll-driven animations on the compositor thread, achieving smooth 60fps performance even on complex pages. Previously, some scroll-driven animations in Safari could cause jank due to main-thread involvement. This optimization brings Safari's performance in line with Chrome's compositor-based approach, meaning you can confidently ship scroll-driven animations knowing they will be smooth across all major browsers.
