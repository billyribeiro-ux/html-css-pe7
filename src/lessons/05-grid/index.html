Level 2 - Layout Mastery

Two-Dimensional Power

CSS Grid gives you simultaneous control over rows and columns — the most powerful layout system CSS has ever had.

1. Grid Container

CSS Grid Layout begins with display: grid on a container element. Just like Flexbox, this turns direct children into grid items. But unlike Flexbox, Grid operates in two dimensions simultaneously. You define both columns and rows up front, creating a structured grid that items flow into.

The two foundational properties are grid-template-columns and grid-template-rows. Each accepts a space-separated list of track sizes. For example, grid-template-columns: 200px 200px 200px creates three columns, each 200 pixels wide. grid-template-rows: 100px 100px creates two rows, each 100 pixels tall.

Items are placed into cells automatically in source order, filling each row from left to right before moving to the next row. This "auto-placement" behavior means you often do not need to explicitly position items — just define the grid structure and let the browser fill it in.

Grid solves layout challenges that were extremely difficult with older techniques. Multi-column layouts with aligned rows, dashboard interfaces, magazine-style designs — all of these become straightforward. Where Flexbox excels at distributing items along a single axis, Grid excels when you need both rows and columns to align.

Why this matters: Grid does not replace Flexbox — they complement each other. Use Grid when your layout is fundamentally two-dimensional (rows AND columns matter). Use Flexbox when you are distributing items along a single axis. In practice, most pages use both: Grid for the overall page layout, Flexbox for components within grid cells. 
.container {
  display: grid;
  grid-template-columns: 200px 200px 200px;  /* 3 equal columns */
  grid-template-rows: 100px 100px;            /* 2 equal rows */
  gap: 1rem;                                   /* Space between cells */
}

/* Items flow into cells automatically:
   Item 1 -> row 1, col 1
   Item 2 -> row 1, col 2
   Item 3 -> row 1, col 3
   Item 4 -> row 2, col 1
   ... and so on */

2. The fr Unit

While pixel values work, they create rigid grids. The fr (fractional) unit is Grid's most important innovation. One fr represents one fraction of the available space in the grid container. If you write grid-template-columns: 1fr 1fr 1fr, the three columns share the available width equally. 1fr 2fr 1fr gives the middle column twice as much space as the others.

The fr unit distributes space after fixed-size tracks and gaps have been accounted for. So grid-template-columns: 200px 1fr 1fr first reserves 200px for the first column, then splits the remaining space equally between the second and third columns. This makes fr perfect for mixing fixed and flexible tracks.

Compared to percentages, fr is more intuitive and more powerful. Percentages do not account for gaps — if you have three 33.33% columns with gaps, the total exceeds 100% and items overflow. The fr unit handles gaps automatically because it distributes only the remaining space.

Why this matters: The fr unit eliminates the math that percentage-based layouts required. No more calculating calc(33.33% - 20px) to account for gutters. Just write 1fr 1fr 1fr and let the browser handle it. This makes Grid layouts inherently more maintainable and less error-prone. 
/* Equal thirds */
grid-template-columns: 1fr 1fr 1fr;

/* Sidebar + main content */
grid-template-columns: 250px 1fr;

/* Proportional: 1:2:1 ratio */
grid-template-columns: 1fr 2fr 1fr;

/* Mixed: fixed, flexible, fixed */
grid-template-columns: 80px 1fr 80px;

3. repeat() and minmax()

Writing 1fr 1fr 1fr 1fr 1fr 1fr for six equal columns is tedious. The repeat() function shortens this to repeat(6, 1fr). The first argument is the count, the second is the track size pattern. You can repeat multiple values: repeat(3, 1fr 2fr) creates six columns alternating 1fr and 2fr.

The minmax() function sets a minimum and maximum size for a track. For example, minmax(200px, 1fr) means "at least 200px, but grow to fill available space." This is incredibly useful for responsive layouts because tracks can adapt while respecting minimum and maximum constraints.

The real magic happens when you combine repeat() with auto-fill or auto-fit and minmax(). The expression repeat(auto-fill, minmax(200px, 1fr)) creates as many columns as will fit, each at least 200px wide, distributing extra space equally. This creates a fully responsive grid without any media queries.

Why this matters: The pattern repeat(auto-fill, minmax(min, 1fr)) is one of the most powerful one-liners in all of CSS. It creates intrinsically responsive layouts that adapt to any container width. Cards, image galleries, product grids — all can be built with this single declaration. Learn this pattern and you will use it constantly. 
/* repeat() shorthand */
grid-template-columns: repeat(3, 1fr);           /* Three equal columns */
grid-template-columns: repeat(4, 150px);          /* Four 150px columns */
grid-template-columns: repeat(3, 1fr 2fr);        /* Six columns: 1fr 2fr 1fr 2fr 1fr 2fr */

/* minmax() for flexible tracks */
grid-template-columns: repeat(3, minmax(100px, 1fr));

/* The responsive grid pattern (no media queries!) */
grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));

4. auto-fill vs auto-fit

Both auto-fill and auto-fit create as many tracks as will fit in the container, but they behave differently when there are fewer items than available tracks. Understanding the difference is crucial for choosing the right one.

auto-fill creates as many tracks as possible, even if some are empty. The empty tracks still take up space. This means items stay at their minimum size and do not stretch to fill the entire container when there are few items.

auto-fit also creates as many tracks as possible, but it collapses empty tracks to zero width. This means the existing items expand to fill all available space. With few items, auto-fit makes them grow wider, while auto-fill keeps them at their minimum size.

In practice: use auto-fit when you want items to stretch and fill the row (common for card layouts). Use auto-fill when you want items to maintain consistent sizing regardless of how many there are (common for image galleries where uniform sizing matters).

Why this matters: The difference only shows when items do not fill the row. With many items both behave identically. But with 2-3 items in a wide container, the difference is dramatic. Choosing wrong can make a 2-card layout look either elegantly spacious (auto-fill) or properly filled (auto-fit). 
/* auto-fill: keeps empty tracks, items stay at minmax minimum */
grid-template-columns: repeat(auto-fill, minmax(150px, 1fr));

/* auto-fit: collapses empty tracks, items stretch to fill */
grid-template-columns: repeat(auto-fit, minmax(150px, 1fr));

5. Grid Areas

Grid areas provide a visual, intuitive way to define layouts. Instead of specifying row and column numbers, you draw an ASCII art map of your layout using grid-template-areas. Each string represents a row, and each name within it represents a cell. Items are assigned to areas using the grid-area property.

Named areas must form rectangles — L-shapes or other non-rectangular shapes are invalid. Use a period (.) for empty cells. The area names you choose are entirely up to you, but semantic names like "header," "sidebar," "content," and "footer" make your layout self-documenting.

Grid areas are perhaps the most readable way to define a layout in CSS. Anyone looking at the template string can immediately visualize the page structure. This makes maintenance dramatically easier compared to numeric row/column placement, where you must mentally map numbers to positions.

When combined with media queries, grid areas make responsive layouts trivial. You simply redefine grid-template-areas at each breakpoint to rearrange the layout. The HTML stays the same; only the CSS grid map changes.

Why this matters: Grid areas are the most readable layout mechanism CSS has ever offered. A developer can glance at the template-areas string and instantly understand the page layout. This drastically reduces the cognitive load of maintaining complex layouts and makes responsive redesigns as simple as redrawing the ASCII map. 
.page {
  display: grid;
  grid-template-areas:
    "header  header  header"
    "sidebar content content"
    "footer  footer  footer";
  grid-template-columns: 200px 1fr 1fr;
  grid-template-rows: auto 1fr auto;
  gap: 1rem;
  min-height: 400px;
}

.page-header  { grid-area: header; }
.page-sidebar { grid-area: sidebar; }
.page-content { grid-area: content; }
.page-footer  { grid-area: footer; }

/* Responsive: single column on mobile */
@media (max-width: 768px) {
  .page {
    grid-template-areas:
      "header"
      "content"
      "sidebar"
      "footer";
    grid-template-columns: 1fr;
  }
}

6. Grid Item Placement

While auto-placement works for simple grids, explicit placement gives you precise control. The grid-column and grid-row properties let you specify exactly where an item should start and end. The syntax uses line numbers — a 3-column grid has 4 column lines (numbered 1 through 4).

The shorthand grid-column: 1 / 3 means "start at column line 1, end at column line 3" (spanning two columns). You can also use the span keyword: grid-column: span 2 means "span two columns from wherever auto-placement puts me." Similarly, grid-row: 1 / span 2 means "start at row 1, span 2 rows."

Negative line numbers count from the end. grid-column: 1 / -1 spans from the first line to the last, making the item full-width regardless of how many columns exist. This is particularly useful for header and footer elements that should always span the entire grid.

Why this matters: Explicit placement is what makes Grid truly two-dimensional. You can place items in any cell, span them across multiple cells, and even overlap them. This is impossible with Flexbox. Mastering line-based placement gives you pixel-perfect control over complex layouts like magazine pages, dashboards, and image mosaics. 
.full-width {
  grid-column: 1 / -1;              /* Span all columns */
}

.feature {
  grid-column: 1 / 3;               /* Columns 1-2 */
  grid-row: 2 / 4;                   /* Rows 2-3 */
}

.sidebar {
  grid-column: span 1;              /* Span 1 column */
  grid-row: span 3;                  /* Span 3 rows */
}

7. Implicit Grid

When you place items beyond the explicitly defined grid, or when auto-placement needs more rows than you defined, the browser creates implicit tracks. By default these tracks are sized to auto (fitting their content). You can control their size with grid-auto-rows and grid-auto-columns.

For example, if you define grid-template-columns: repeat(3, 1fr) but no rows, the browser creates rows automatically as items are placed. Setting grid-auto-rows: 150px makes every auto-created row exactly 150px tall. Using grid-auto-rows: minmax(100px, auto) gives them a minimum height of 100px but allows them to grow for taller content.

The grid-auto-flow property controls how auto-placed items fill the grid. The default is row, filling each row left-to-right before starting a new row. Setting grid-auto-flow: column fills columns top-to-bottom instead. Adding the dense keyword (grid-auto-flow: row dense) allows the browser to backfill gaps left by larger spanning items, creating a more compact layout.

Why this matters: The implicit grid is what makes Grid work well with dynamic content. When you do not know how many items you will have (a CMS blog listing, a product catalog), you define columns and let the implicit grid handle rows. Use grid-auto-rows to ensure consistent row heights without knowing the count. 
.container {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  grid-auto-rows: minmax(100px, auto);  /* Implicit rows: at least 100px */
  grid-auto-flow: row dense;             /* Fill gaps when possible */
  gap: 1rem;
}

8. Gap

The gap property adds space between grid tracks (rows and columns). It is the successor to the older grid-gap property and now works in both Grid and Flexbox contexts. The shorthand gap: 1rem sets equal row and column gaps. You can set them independently with row-gap and column-gap.

Unlike margins, gap only creates space between items — never at the outer edges. This eliminates the classic problem of needing to remove the margin from the last item in a row. Gap also interacts correctly with the fr unit: fractional units distribute space after gaps have been subtracted.

You can use any length unit for gap: pixels, rems, percentages, or even calc() expressions. Percentage gaps are relative to the grid container's size in the relevant dimension. For most use cases, rem values provide the most predictable and maintainable spacing.

Why this matters: Consistent spacing is a hallmark of professional design. The gap property gives you that consistency with zero effort. No more negative margin hacks, no more :last-child overrides, no more miscounting gutters. It just works. 
/* Equal gap in both directions */
gap: 1rem;

/* Different row and column gaps */
row-gap: 2rem;
column-gap: 1rem;

/* Shorthand: row-gap / column-gap */
gap: 2rem 1rem;

9. Dashboard Layout

Dashboards are a perfect use case for CSS Grid. They typically consist of a navigation bar across the top, a sidebar on the left, and a main content area filled with cards of varying sizes. Grid areas make the overall structure clear, and nested grids handle the card layout within the main content area.

The dashboard below uses grid-template-areas for the outer layout and repeat(auto-fill, minmax(...)) for the inner card grid. Some cards span two columns to highlight important metrics. This is a pattern you will see in virtually every admin interface, analytics tool, and data visualization platform.

Notice how the entire layout is achieved with pure CSS — no JavaScript, no absolute positioning, no float hacks. The structure is semantic HTML, the layout is declarative CSS, and the result is responsive by nature.

Why this matters: Dashboard layouts are one of the most common requirements in web applications. Mastering the Grid patterns shown here prepares you for real-world projects in enterprise software, SaaS products, and admin panels. The combination of named areas for structure and auto-fill for content is a powerful, repeatable pattern. 
.dashboard {
  display: grid;
  grid-template-areas:
    "nav     nav"
    "sidebar main";
  grid-template-columns: 220px 1fr;
  grid-template-rows: auto 1fr;
  min-height: 400px;
}

.dash-cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(180px, 1fr));
  gap: 1rem;
}

.dash-card-wide {
  grid-column: span 2;
}

  • A full-width footer at the bottom.
  • Use grid-template-areas for the layout structure.
