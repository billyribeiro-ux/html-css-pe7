Masonry Layout

Build Pinterest-style layouts natively in CSS with display: masonry. Define column tracks, control item flow, span featured content across columns, and ship responsive masonry grids with progressive enhancement fallbacks.

1. The Masonry Problem

You have seen it everywhere: Pinterest, Unsplash, Dribbble. A grid of cards or images where items have different heights and pack tightly together without leaving gaps. The items flow into columns, and each new item slots into whichever column has the most room. That is masonry layout.

CSS Grid cannot do this. Grid is a two-dimensional layout engine: it defines explicit rows and columns, and every item in a row shares the same row height. If one card is tall and another is short, Grid leaves a gap below the short card. You can use grid-auto-rows: masonry as proposed in earlier specs, but that approach was never shipped. CSS Columns can approximate the look, but items flow top-to-bottom within each column rather than row-by-row, which breaks the expected reading order.

JavaScript libraries like Masonry.js, Isotope, and Packery solved this for years. They measure each item's height, calculate positions, and apply absolute positioning. The downsides: a flash of unstyled content before JS runs, expensive reflows on resize, layout shifts that hurt Core Web Vitals, and a runtime dependency for what should be a CSS concern.

display: masonry is the native CSS answer. It gives the browser full control over the packing algorithm, runs on the compositor thread, and requires zero JavaScript. Items flow left-to-right (or right-to-left) across column tracks, and each item drops into the shortest column. The result is a tight, gap-free layout that responds to container size changes instantly.

Key Insight: Masonry is not a variation of Grid. It is a distinct layout mode with its own display value, its own track properties, and its own packing algorithm. The CSS Working Group chose display: masonry as a first-class citizen rather than bolting it onto Grid because the layout semantics are fundamentally different.

2. display: masonry

The foundation is simple. Set display: masonry on a container and define your column tracks with masonry-template-tracks. Items flow into columns left-to-right, and each item is placed in whichever column is currently shortest.

CSS

/* Basic masonry: three equal columns */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  gap: 1rem;
}

/* Four columns with explicit widths */
.portfolio {
  display: masonry;
  masonry-template-tracks: 200px 300px 200px 300px;
  gap: 1.5rem;
}

/* Auto-sized columns that fill available space */
.feed {
  display: masonry;
  masonry-template-tracks: repeat(auto-fill, minmax(250px, 1fr));
  gap: 1rem;
}

masonry-template-tracks

This property defines the column tracks, using the same track-sizing syntax you already know from Grid: fixed lengths, fr units, minmax(), repeat(), auto-fill, and auto-fit. The key difference: these tracks only define columns (the stacking axis). The cross axis (row heights) is determined by each item's intrinsic content height.

masonry-auto-tracks

When items exceed the explicitly defined tracks, masonry-auto-tracks controls the size of implicitly created columns. It works the same way grid-auto-columns does for Grid.

CSS

/* If more items need columns beyond the template */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  masonry-auto-tracks: 200px;
  gap: 1rem;
}

gap

The gap property works exactly as it does in Grid and Flexbox. Use a single value for uniform spacing or two values for row-gap and column-gap separately. The gap is applied between items both horizontally (between columns) and vertically (between stacked items within a column).

CSS

/* Uniform gap */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  gap: 1rem;
}

/* Different row and column gaps */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  gap: 0.75rem 1.5rem; /* row-gap column-gap */
}

3. masonry-direction

By default, masonry items flow across columns from left to right. The masonry-direction property lets you change that. You have four options:

CSS

/* Default: items fill columns left-to-right */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  masonry-direction: column;
}

/* Items fill columns right-to-left */
.gallery-rtl {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  masonry-direction: column-reverse;
}

/* Row masonry: tracks define rows, items flow top-to-bottom */
.horizontal-feed {
  display: masonry;
  masonry-template-tracks: repeat(3, 200px);
  masonry-direction: row;
}

/* Row masonry reversed */
.horizontal-feed-reverse {
  display: masonry;
  masonry-template-tracks: repeat(3, 200px);
  masonry-direction: row-reverse;
}

Column vs Row Masonry

Column masonry (the default) is the Pinterest model. Tracks define columns, items have variable heights, and each item drops into the shortest column. Use this for image galleries, card feeds, and any vertical-scrolling layout.

Row masonry flips the axis. Tracks define rows, items have variable widths, and each item slots into the shortest row. This is useful for horizontal timelines, tag clouds, and horizontally-scrolling panels where items vary in width.

Key Insight: When using masonry-direction: row, the masonry-template-tracks property defines row heights instead of column widths. The browser then packs items horizontally into whichever row is currently shortest. Think of it as rotating the entire masonry algorithm 90 degrees.

4. masonry-auto-flow

The masonry-auto-flow property controls how the browser decides where to place each item. There are two dimensions to this decision: the placement algorithm and the ordering.

CSS

/* Default: pack items into the shortest column, maintain DOM order */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  masonry-auto-flow: pack;
}

/* Place items sequentially (round-robin), no packing optimization */
.feed {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  masonry-auto-flow: next;
}

/* Pack items into shortest column, allow reordering for tighter fit */
.gallery-optimized {
  display: masonry;
  masonry-template-tracks: repeat(3, 1fr);
  masonry-auto-flow: pack ordered;
}

pack vs next

pack (default) always places the next item into whichever column is currently shortest. This produces the tightest layout with minimal gaps, but items may appear out of visual order when viewed left-to-right, row-by-row.

next places items in columns sequentially: item 1 goes in column 1, item 2 in column 2, item 3 in column 3, then item 4 wraps back to column 1. This preserves a more predictable reading order but can leave larger gaps when item heights vary significantly.

ordered vs unordered

When combined with pack, the ordered keyword tells the browser it can reorder items from the DOM source order to achieve a tighter packing. Without ordered, items maintain their DOM order even with pack placement. Use ordered for decorative layouts like photo galleries. Avoid it for content where reading order matters, like article feeds or navigation lists.

5. Spanning Items

Sometimes you want a featured item to span multiple columns. The masonry-track property (shorthand for masonry-track-start and masonry-track-end) controls how many columns an item occupies.

CSS

/* Featured item spans two columns */
.card--featured {
  masonry-track: span 2;
}

/* Hero item spans all three columns */
.card--hero {
  masonry-track: span 3;
}

/* Place an item in a specific column */
.card--sidebar {
  masonry-track: 3; /* Third column */
}

/* Place and span: start at column 2, span 2 columns */
.card--wide {
  masonry-track: 2 / span 2;
}

Spanning works the same way as grid-column: span N in CSS Grid. The browser calculates how to pack the remaining items around the spanning element. If a spanning item cannot fit at its natural position (because there are not enough remaining columns), it wraps to the next row of items.

Key Insight: When an item spans multiple columns, it creates a horizontal "barrier" in the masonry flow. Items above and below it pack independently. This is intentional: the browser must ensure the spanning item aligns cleanly across its columns. Keep spanning items relatively infrequent (hero cards, featured posts) to avoid disrupting the flow too much.

6. Responsive Masonry

Building responsive masonry layouts follows the same patterns you use with Grid. The most powerful technique is auto-fill with minmax(), which lets the browser decide how many columns fit at any viewport width.

CSS

/* Fluid columns: as many as fit, minimum 250px each */
.gallery {
  display: masonry;
  masonry-template-tracks: repeat(auto-fill, minmax(250px, 1fr));
  gap: 1rem;
}

/* Same thing with auto-fit (collapses empty tracks) */
.gallery-fit {
  display: masonry;
  masonry-template-tracks: repeat(auto-fit, minmax(250px, 1fr));
  gap: 1rem;
}

Media Query Breakpoints

You can also use media queries to switch between fixed column counts at specific breakpoints. This gives you precise control over column counts at each size.

CSS

/* Mobile: single column */
.gallery {
  display: masonry;
  masonry-template-tracks: 1fr;
  gap: 1rem;
}

/* Tablet: two columns */
@media (min-width: 640px) {
  .gallery {
    masonry-template-tracks: repeat(2, 1fr);
  }
}

/* Desktop: three columns */
@media (min-width: 1024px) {
  .gallery {
    masonry-template-tracks: repeat(3, 1fr);
  }
}

/* Wide: four columns */
@media (min-width: 1440px) {
  .gallery {
    masonry-template-tracks: repeat(4, 1fr);
    gap: 1.5rem;
  }
}

Container Queries + Masonry

Even more powerful: combine masonry with container queries. This lets a masonry grid adapt its column count based on the container's width rather than the viewport, making it truly reusable as a component.

CSS

.gallery-wrapper {
  container-type: inline-size;
}

.gallery {
  display: masonry;
  masonry-template-tracks: 1fr;
  gap: 1rem;
}

@container (min-width: 500px) {
  .gallery {
    masonry-template-tracks: repeat(2, 1fr);
  }
}

@container (min-width: 800px) {
  .gallery {
    masonry-template-tracks: repeat(3, 1fr);
  }
}

@container (min-width: 1100px) {
  .gallery {
    masonry-template-tracks: repeat(4, 1fr);
  }
}

7. Progressive Enhancement

As of mid-2026, display: masonry is landing in browsers but is not universally supported yet. You need a fallback strategy. The good news: CSS gives you everything you need with @supports.

Strategy 1: CSS Columns Fallback

CSS multi-column layout (column-count) is the simplest fallback. It produces a similar visual result, though items flow top-to-bottom within columns rather than left-to-right across them. For image galleries and decorative layouts, this is perfectly acceptable.

CSS

/* Baseline: CSS Columns fallback */
.gallery {
  column-count: 3;
  column-gap: 1rem;
}

.gallery > * {
  break-inside: avoid;
  margin-bottom: 1rem;
}

/* Enhancement: native masonry when supported */
@supports (display: masonry) {
  .gallery {
    display: masonry;
    masonry-template-tracks: repeat(3, 1fr);
    gap: 1rem;

    /* Reset column fallback */
    column-count: unset;
  }

  .gallery > * {
    break-inside: unset;
    margin-bottom: unset;
  }
}

Strategy 2: Grid Fallback

If you need items to flow left-to-right (preserving reading order), use CSS Grid as the fallback. Items will have uniform row heights (leaving gaps), but the column structure and reading order will be correct. When masonry support arrives, the gaps disappear.

CSS

/* Baseline: CSS Grid (has gaps, but correct order) */
.gallery {
  display: grid;
  grid-template-columns: repeat(3, 1fr);
  gap: 1rem;
}

/* Enhancement: masonry eliminates the gaps */
@supports (display: masonry) {
  .gallery {
    display: masonry;
    masonry-template-tracks: repeat(3, 1fr);
  }
}

Strategy 3: Flexbox Wrap Fallback

For simple card layouts where exact column alignment is less important, flex-wrap works as a baseline. Items wrap naturally and fill the row.

CSS

/* Baseline: Flexbox wrap */
.gallery {
  display: flex;
  flex-wrap: wrap;
  gap: 1rem;
}

.gallery > * {
  flex: 1 1 calc(33.333% - 1rem);
  min-width: 250px;
}

/* Enhancement: masonry for tight packing */
@supports (display: masonry) {
  .gallery {
    display: masonry;
    masonry-template-tracks: repeat(auto-fill, minmax(250px, 1fr));
  }

  .gallery > * {
    flex: unset;
    min-width: unset;
  }
}

8. display: grid-lanes (Safari 26.4)

In March 2026, Safari 26.4 shipped an alternative approach to masonry layout: display: grid-lanes. While Chrome and Firefox have been implementing display: masonry as a standalone layout mode, Safari chose to integrate masonry-like behavior directly into the CSS Grid specification under a new display value.

The grid-lanes approach reuses familiar Grid syntax — grid-template-columns, gap, and other Grid properties — but adds masonry packing behavior for the cross axis. Items flow into whichever column (lane) is shortest, just like display: masonry, but the implementation is built on top of Grid internals rather than a separate layout algorithm.

CSS

/* Safari's grid-lanes approach */
.gallery {
  display: grid-lanes;
  grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
  flow-tolerance: 50px;
  gap: 1rem;
}

/* flow-tolerance controls how much height difference the browser
   tolerates before moving an item to a shorter column.
   A higher value produces a more "relaxed" pack with better
   reading order; a lower value produces tighter packing. */

/* Items can still span multiple lanes */
.featured {
  grid-column: span 2;
}

The unique addition in grid-lanes is the flow-tolerance property. This controls how aggressively items are packed into the shortest column versus maintaining natural document order. A flow-tolerance: 0 always places items in the shortest column (maximum packing), while a higher value keeps items closer to their natural order, only moving them to a shorter column when the height difference exceeds the tolerance threshold.

The Spec Debate: masonry vs. grid-lanes

The CSS Working Group has been debating the best approach to native masonry since 2020. Two camps emerged: one favoring display: masonry as a completely separate layout mode (championed by Chrome/Google engineers), and another favoring integration into Grid (championed by Apple/WebKit engineers who shipped grid-lanes). Safari shipped grid-lanes first in March 2026. The arguments for each approach:

  • display: masonry — Cleaner separation of concerns; masonry has fundamentally different packing semantics than Grid; avoids overloading Grid with behaviors that violate its two-dimensional contract.
  • display: grid-lanes — Reuses existing Grid knowledge and tooling; easier migration path for developers already using Grid; leverages existing Grid features like named lines and grid-column: span N.

Both approaches may coexist in the final specification. For now, use @supports to provide the appropriate implementation for each browser, and use display: masonry or display: grid-lanes depending on which browser supports which.

CSS (Progressive Enhancement for Both)

/* Baseline fallback */
.gallery {
  column-count: 3;
  column-gap: 1rem;
}

.gallery > * {
  break-inside: avoid;
  margin-bottom: 1rem;
}

/* Safari's grid-lanes */
@supports (display: grid-lanes) {
  .gallery {
    display: grid-lanes;
    grid-template-columns: repeat(auto-fill, minmax(250px, 1fr));
    flow-tolerance: 50px;
    gap: 1rem;
    column-count: unset;
  }
  .gallery > * {
    break-inside: unset;
    margin-bottom: unset;
  }
}

/* Chrome/Firefox masonry */
@supports (display: masonry) {
  .gallery {
    display: masonry;
    masonry-template-tracks: repeat(auto-fill, minmax(250px, 1fr));
    gap: 1rem;
    column-count: unset;
  }
  .gallery > * {
    break-inside: unset;
    margin-bottom: unset;
  }
}

Exercise: Image Gallery

Requirements

  • Create a gallery container with at least 8 image cards of varying heights (use colored placeholders with different heights).
  • Baseline: use column-count: 3 with column-gap: 1rem. Each card needs break-inside: avoid and margin-bottom: 1rem.
  • Enhancement: wrap display: masonry with masonry-template-tracks: repeat(3, 1fr) inside @supports (display: masonry). Reset the column properties.
  • Add a responsive breakpoint: at max-width: 640px, switch to 2 columns (both in the fallback and the masonry enhancement).
  • One card should be a "featured" card that spans 2 columns in masonry mode (use masonry-track: span 2).
  • Add hover effects: scale up slightly and increase box-shadow.
  • Cards should have rounded corners, a subtle border, and a dark background matching the theme.

Challenge: Portfolio Showcase

Build a complete portfolio page using masonry layout with all the techniques from this module: responsive tracks, featured spanning items, masonry-auto-flow, and progressive enhancement.

Requirements

  • Layout: Use display: masonry with repeat(auto-fill, minmax(280px, 1fr)) for a fluid column count that adapts from 1 to 4+ columns.
  • Featured Items: At least 2 cards should use masonry-track: span 2 to span two columns. Give them a distinct visual treatment (border accent, larger image, "Featured" badge).
  • Flow Control: Use masonry-auto-flow: pack for tight packing. Add a comment showing the next alternative.
  • Categories: Include at least 10 portfolio cards with project images (gradient placeholders), titles, descriptions, and category tags (Design, Development, Branding, etc.).
  • Hover Effects: Cards should lift on hover with translateY(-6px), an increased shadow, and a border color shift to the accent color.
  • Progressive Enhancement: Write CSS Columns as the baseline. Wrap all masonry properties in @supports (display: masonry).
  • Responsive: At max-width: 640px, the featured cards should revert to masonry-track: span 1 (single column).
  • Dark Theme: Use the dark color scheme (#0f1117 background, #e4e6ef text, #6c5ce7 accent).

Architecture Hints

  • Start with the CSS Columns fallback first, get the layout looking good, then layer in @supports (display: masonry).
  • Use gradient backgrounds for the image placeholders: linear-gradient(135deg, color1, color2).
  • Give featured cards a left border accent: border-left: 4px solid #6c5ce7.
  • For category tags, use small inline elements with display: inline-block, a subtle background, and rounded corners.
  • Consider adding masonry-direction: column explicitly for clarity, even though it is the default.
