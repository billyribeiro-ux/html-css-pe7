One-Dimensional Flow

Master Flexbox to build layouts that flow naturally along a single axis — the backbone of modern CSS layout.

1. What is Flexbox

Flexbox — short for Flexible Box Layout — is a CSS layout model designed for one-dimensional arrangement of items. "One-dimensional" means you control layout along a single axis at a time: either a row (horizontal) or a column (vertical). This stands in contrast to CSS Grid, which handles two dimensions simultaneously.

Every flex layout has two axes. The main axis runs in the direction you set with flex-direction (horizontal by default). The cross axis runs perpendicular to it. When the main axis is horizontal, the cross axis is vertical, and vice versa. Every Flexbox property maps to one of these two axes, so internalizing this mental model is the key to mastering the system.

Before Flexbox, developers used floats, inline-block hacks, and table-display tricks to achieve horizontal layouts. Each approach came with painful edge cases: collapsed parent heights, whitespace bugs, and vertical-alignment nightmares. Flexbox was purpose-built to replace all of them with a clean, predictable model for distributing space and aligning content in one direction.

When to use Flex vs Grid: Use Flexbox whenever your layout flows in one direction — navigation bars, card rows, form controls, media objects, toolbars, button groups. Use CSS Grid when you need simultaneous row-and-column control, such as page-level layouts, dashboards, or image galleries with precise placement. In practice, most components are one-dimensional, making Flexbox your most-used layout tool.

2. Flex Container

Flexbox begins with a single declaration: display: flex. The moment you apply this to an element, it becomes a flex container, and every direct child becomes a flex item. This fundamentally changes how the children are laid out — instead of following normal block or inline flow, they arrange themselves along the main axis.

The main axis is controlled by the flex-direction property. By default it is row, which runs left-to-right in left-to-right languages. You can flip it to row-reverse (right-to-left), column (top-to-bottom), or column-reverse (bottom-to-top). Understanding that every flex layout has a main axis and a cross axis (perpendicular to it) is the single most important mental model for mastering Flexbox.

There is also display: inline-flex, which makes the container behave as an inline-level element (like inline-block) while still establishing a flex formatting context for its children. Use this when you want a flex container to sit within a line of text or alongside other inline elements. 

<div class="container">
  <div class="item">A</div>
  <div class="item">B</div>
  <div class="item">C</div>
</div>

<style>
.container {
  display: flex;               /* Activates Flexbox */
  flex-direction: row;         /* Main axis: horizontal (default) */
}

/* Try these alternatives: */
/* flex-direction: row-reverse;    Right to left */
/* flex-direction: column;         Top to bottom */
/* flex-direction: column-reverse; Bottom to top */
</style>

3. justify-content

Once you have established a flex container and its direction, the next question is: how should the items be distributed along the main axis? That is the job of justify-content. This property controls where items sit and how leftover space is distributed between them.

There are six key values. flex-start packs items to the start of the main axis (the default). flex-end packs them to the end. center clusters them in the middle. space-between puts the first item at the start, the last at the end, and distributes remaining space equally between items. space-around gives each item equal space on both sides (so the gap between two items is double the gap at the edges). space-evenly distributes space so that the gap between any two adjacent items — and the gap before the first and after the last — are all identical.

The difference between space-around and space-evenly is subtle but important. With space-around, edge items get half the spacing that inner items get. With space-evenly, every gap is the same. In practice, space-evenly tends to look more balanced and is usually what designers intend.

Why this matters: Understanding justify-content eliminates the need for margin hacks and spacer elements. Instead of manually computing margins to spread items out, you let the browser do the math. This is more robust, more readable, and adapts automatically when items are added or removed. 
.container {
  display: flex;
  justify-content: space-between;
}

/* All possible values: */
/* justify-content: flex-start;    Pack to start (default) */
/* justify-content: flex-end;      Pack to end */
/* justify-content: center;        Center items */
/* justify-content: space-between; Space between items only */
/* justify-content: space-around;  Equal space around each item */
/* justify-content: space-evenly;  Equal space everywhere */

4. align-items

While justify-content handles the main axis, align-items controls how flex items are positioned along the cross axis (perpendicular to the main axis). In a row layout, the cross axis runs vertically. In a column layout, it runs horizontally. This property is set on the flex container and affects all items.

The default value is stretch, which makes items expand to fill the container's cross-axis dimension. This is why flex items in a row layout all become the same height by default — they stretch to match the tallest item. Other values include flex-start (align to the top/left of the cross axis), flex-end (align to the bottom/right), center (center on the cross axis), and baseline (align by text baseline).

The baseline value deserves special attention. It aligns items so that the text baselines of each item line up. This is especially useful when items have different font sizes or different amounts of padding above their text. Without baseline alignment, text in adjacent flex items can look misaligned even when the boxes themselves are aligned.

Why this matters: Cross-axis alignment is what makes Flexbox a complete layout tool rather than just a float replacement. The ability to vertically center items in a row — something that was notoriously difficult before Flexbox — is now a single property. align-items: center is one of the most-used CSS declarations in modern web development. 
.container {
  display: flex;
  align-items: center;       /* All items centered on cross axis */
  height: 200px;             /* Need height to see cross-axis effect */
}

5. flex-wrap & gap

By default, flex items try to fit onto a single line. If the items' combined size exceeds the container's width, they shrink (governed by flex-shrink) rather than wrapping. You can change this with flex-wrap: wrap, which allows items to flow onto additional lines when there is not enough room.

Wrapping transforms Flexbox from a strictly single-line tool into something that can handle multi-line layouts. When items wrap, each line becomes its own "flex line" with independent alignment. The align-content property controls how multiple flex lines are distributed on the cross axis — similar to how justify-content distributes items on the main axis.

The gap property (and its longhands row-gap and column-gap) adds consistent spacing between flex items without margin hacks. Unlike margins, gap only appears between items — never at the edges. This solves the classic "last-child margin" problem. Gap works beautifully with wrapping: items on different lines get the row-gap between them.

Why this matters: The combination of flex-wrap: wrap and gap creates intrinsically responsive layouts. A row of cards that naturally wraps when space runs out, with consistent gutters, requires no media queries. This is the foundation of many real-world component layouts. 
.card-container {
  display: flex;
  flex-wrap: wrap;          /* Allow items to wrap to new lines */
  gap: 1rem;                /* Space between items (row and column) */
}

.card {
  flex: 1 1 250px;          /* Grow/shrink from a 250px base */
  /* Cards will be at least ~250px wide and wrap when they can't fit */
}

/* align-content controls multi-line distribution */
.multi-line {
  align-content: space-between; /* Spread lines across cross axis */
}

6. Flex Items: grow, shrink, basis

Beyond alignment, Flexbox provides fine-grained control over how individual items consume available space. Three properties govern this: flex-grow, flex-shrink, and flex-basis. Together, they determine how an item expands into extra space, how it contracts when space is tight, and what its ideal starting size should be.

flex-grow is a unitless number (defaulting to 0) that defines how much of the remaining space an item should absorb. If all items have flex-grow: 1, they share leftover space equally. If one item has flex-grow: 2 and the others have flex-grow: 1, it absorbs twice as much extra space as each of the others. Crucially, this distributes extra space — it does not make the item twice as wide overall.

flex-shrink works in reverse (defaulting to 1). When items overflow the container, each item shrinks proportionally to its shrink factor. Setting flex-shrink: 0 prevents an item from shrinking at all, which is useful for fixed-width elements like icons or action buttons.

flex-basis sets the initial size before growing or shrinking. It accepts any length value or auto (which uses the item's width/height). Setting flex-basis: 0 means the item starts at zero size and all space is distributed by grow factors, giving you truly proportional sizing.

Why this matters: The flex shorthand (flex: grow shrink basis) is the recommended way to set these. Common patterns: flex: 1 (grow equally, basis 0), flex: 0 0 auto (rigid, no grow/shrink), flex: 1 1 200px (grow/shrink from 200px base). Use the shorthand because it sets sensible defaults for values you omit. 
.item-a { flex: 1; }           /* flex-grow:1, flex-shrink:1, flex-basis:0 */
.item-b { flex: 2; }           /* Absorbs twice as much extra space */
.item-c { flex: 0 0 200px; }   /* Fixed at 200px, no grow, no shrink */
.item-d { flex: 1 1 300px; }   /* Starts at 300px, can grow and shrink */

/* The longhand equivalents: */
.item-a {
  flex-grow: 1;
  flex-shrink: 1;
  flex-basis: 0;
}

7. align-self & order

While align-items sets the cross-axis alignment for all items at once, align-self lets you override that alignment for a single item. It accepts all the same values: stretch, flex-start, flex-end, center, and baseline. This is particularly useful for creating asymmetric layouts where one element needs special positioning.

The order property lets you visually reorder flex items without changing the HTML source order. Every flex item defaults to order: 0. Items are laid out in ascending order value — items with lower values come first. Items with the same order value appear in their source order. You can use negative values to move items before the default position.

However, there is an important accessibility caveat. Screen readers and keyboard navigation follow the source order, not the visual order. If you use order extensively, the visual layout can diverge from the tab order, creating a confusing experience for keyboard users. Use order sparingly and always test with keyboard navigation. 

/* align-self overrides the container's align-items for one item */
.container { align-items: center; }
.special   { align-self: flex-end; }

/* order reorders items visually */
.item-a { order: 3; }   /* Appears last */
.item-b { order: 1; }   /* Appears first */
.item-c { order: 2; }   /* Appears second */
/* Visual: B, C, A — but source (for accessibility): A, B, C */

8. Pattern: Perfect Centering

Centering both horizontally and vertically was CSS's most notorious challenge for over a decade. Developers tried margin: 0 auto, table cells, absolute positioning with negative margins, and transform: translate(-50%, -50%). Each hack had limitations. Flexbox solves it with two properties and no compromises.

The pattern is simply: display: flex, justify-content: center (centers on the main axis), and align-items: center (centers on the cross axis). Add a height to the container and the child is perfectly centered regardless of its size. This works for any content — text, images, cards, entire sections.

An even shorter alternative is display: flex on the parent plus margin: auto on the child. In a flex context, margin: auto absorbs all available space in every direction, effectively centering the item. Both approaches produce identical results. 

/* Method 1: Container properties */
.center-parent {
  display: flex;
  justify-content: center;
  align-items: center;
  min-height: 100vh;
}

/* Method 2: margin auto on child */
.center-parent { display: flex; min-height: 100vh; }
.center-child  { margin: auto; }

9. Pattern: Navigation Bar

A classic navigation bar has three zones: a logo on the left, navigation links in the center, and a call-to-action button on the right. This is one of the most common flex patterns in production websites. The trick is giving the center section flex: 1 so it absorbs all available space, then centering its children with nested flex.

The outer nav is a flex container with align-items: center for vertical centering. The logo and CTA button have fixed sizes. The middle <ul> gets flex: 1 and justify-content: center to center the links within the remaining space. The gap property handles spacing between links cleanly.

For responsive behavior, a common approach is to stack all three zones vertically on small screens using flex-direction: column inside a media query, or to hide the links entirely behind a hamburger menu. The flex model makes both strategies straightforward. 

.navbar {
  display: flex;
  align-items: center;
  padding: 1rem 2rem;
}

.navbar-logo { flex: 0 0 auto; }

.navbar-links {
  flex: 1;
  display: flex;
  justify-content: center;
  gap: 1.5rem;
  list-style: none;
}

.navbar-cta { flex: 0 0 auto; }

10. Pattern: Holy Grail Layout

The "Holy Grail" layout has a header, footer, and three columns (left sidebar, main content, right sidebar). It was called the Holy Grail because it was extremely difficult to achieve with pre-Flexbox CSS. With Flexbox, it is straightforward: the outer container uses flex-direction: column and the middle section uses flex-direction: row.

The outer wrapper gets display: flex; flex-direction: column; min-height: 100vh to fill the viewport. The header and footer have fixed sizes. The middle body gets flex: 1 to absorb remaining vertical space. Inside the body, a nested flex row holds the two sidebars (with flex: 0 0 200px for fixed widths) and the main content area (with flex: 1 to absorb remaining horizontal space).

For responsive behavior, a media query switches the body to flex-direction: column on narrow screens, stacking the sidebars above and below the content. You can also use order to ensure the main content appears first on mobile for better content priority. 

.holy-grail {
  display: flex;
  flex-direction: column;
  min-height: 300px;
}

.holy-grail-body {
  display: flex;
  flex: 1;
}

.holy-grail-main    { flex: 1; }
.holy-grail-sidebar { flex: 0 0 150px; }
