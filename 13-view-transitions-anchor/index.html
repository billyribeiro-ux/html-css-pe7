Seamless Navigation & Floating UI

Master the View Transitions API, CSS Anchor Positioning, and the Popover API to create buttery-smooth page transitions, perfectly-placed tooltips, and accessible floating UI — all without JavaScript positioning libraries.

1. View Transitions API

The View Transitions API lets you create smooth, animated transitions between different DOM states or page navigations. Instead of abrupt layout changes, elements can morph seamlessly from one position, size, or appearance to another. The browser captures "before" and "after" snapshots and animates between them.

How It Works

The key CSS property is view-transition-name. When you assign matching transition names to elements in the "old" and "new" states, the browser automatically creates a crossfade/morph animation between them.

CSS

/* Assign a unique transition name to an element */
.hero-card {
  view-transition-name: hero-card;
}

/* The browser generates pseudo-elements you can style */
::view-transition-old(hero-card) {
  animation-duration: 0.4s;
}

::view-transition-new(hero-card) {
  animation-duration: 0.4s;
}

JavaScript (for SPA transitions)

// Trigger a view transition in a single-page app
document.startViewTransition(() => {
  // Update the DOM here — swap layouts, change content
  updateLayout();
});

Important: Each view-transition-name must be unique on the page at any given time. If two visible elements share the same name, the transition will fail. Think of it as a unique ID for animation purposes.

2. @view-transition Rule

For multi-page applications (traditional websites with full page navigations), the @view-transition at-rule enables cross-document transitions without any JavaScript.

CSS (on both pages)

/* Enable cross-document view transitions */
@view-transition {
  navigation: auto;
}

/* Elements with matching view-transition-names
   across pages will morph automatically */
.page-header {
  view-transition-name: page-header;
}

.main-logo {
  view-transition-name: main-logo;
}

.hero-image {
  view-transition-name: hero-image;
}

How MPA Transitions Work

  1. User clicks a link — browser begins navigation to the new page.
  2. Old page snapshot — the browser captures the current visual state of all elements with view-transition-name.
  3. New page renders — the browser renders the new page off-screen and captures the new state of matching named elements.
  4. Animation — the browser animates from old snapshots to new positions/sizes/appearances.
  5. Cleanup — pseudo-elements are removed, the new page is fully interactive.

3. ::view-transition Pseudo-elements

During a view transition, the browser creates a tree of pseudo-elements you can target to customize animations. Understanding this tree is key to creating unique transitions.

Pseudo-element Tree

::view-transition
  └── ::view-transition-group(name)          /* Animates size & position */
       └── ::view-transition-image-pair(name) /* Contains old & new */
            ├── ::view-transition-old(name)    /* Snapshot of old state */
            └── ::view-transition-new(name)    /* Snapshot of new state */

Customizing Transition Animations

CSS

/* Slow down all transitions */
::view-transition-group(*) {
  animation-duration: 0.6s;
  animation-timing-function: cubic-bezier(0.4, 0, 0.2, 1);
}

/* Slide the old content out to the left */
::view-transition-old(main-content) {
  animation: slide-out-left 0.3s ease-in forwards;
}

/* Slide the new content in from the right */
::view-transition-new(main-content) {
  animation: slide-in-right 0.3s ease-out forwards;
}

@keyframes slide-out-left {
  to { transform: translateX(-100%); opacity: 0; }
}

@keyframes slide-in-right {
  from { transform: translateX(100%); opacity: 0; }
}

/* A fancy "morph" for a hero image */
::view-transition-group(hero-image) {
  animation-duration: 0.5s;
  animation-timing-function: cubic-bezier(0.22, 1, 0.36, 1);
}

/* Cross-fade with different timing */
::view-transition-old(hero-image) {
  animation: fade-out 0.25s ease forwards;
}

::view-transition-new(hero-image) {
  animation: fade-in 0.25s 0.15s ease forwards;
}

@keyframes fade-out {
  to { opacity: 0; }
}

@keyframes fade-in {
  from { opacity: 0; }
}

4. CSS Anchor Positioning

Before anchor positioning, placing a tooltip or dropdown relative to a trigger element required JavaScript to measure positions and handle edge cases. CSS Anchor Positioning solves this declaratively.

The Core Concept

You declare an element as an anchor, then position another element relative to that anchor using the anchor() function.

CSS

/* Step 1: Declare the anchor */
.trigger-button {
  anchor-name: --my-trigger;
}

/* Step 2: Position the floating element relative to the anchor */
.tooltip {
  /* Remove from normal flow */
  position: fixed;

  /* Link to the anchor */
  position-anchor: --my-trigger;

  /* Position below the anchor, centered horizontally */
  top: anchor(bottom);
  left: anchor(center);
  translate: -50% 0;

  /* Add some spacing */
  margin-top: 8px;
}

The anchor() Function

The anchor() function accepts a side keyword that refers to the anchor element's edges:

Value Refers to Use with property
anchor(top)Top edge of the anchorbottom
anchor(bottom)Bottom edge of the anchortop
anchor(left)Left edge of the anchorright
anchor(right)Right edge of the anchorleft
anchor(center)Center of the anchor (horizontal or vertical)left, top, or justify-self

.anchor-trigger:focus + .anchor-tooltip {
  opacity: 1;
  pointer-events: auto;
}

5. position-try-fallbacks

What happens when your tooltip or dropdown is near the edge of the viewport and there is not enough space to display it in the preferred position? position-try-fallbacks tells the browser to automatically try alternative positions.

CSS

/* Tooltip prefers to appear below, but will flip above if needed */
.smart-tooltip {
  position: fixed;
  position-anchor: --smart-anchor;

  /* Preferred position: below */
  top: anchor(bottom);
  left: anchor(center);
  translate: -50% 0;
  margin-top: 8px;

  /* Fallback positions to try */
  position-try-fallbacks: flip-block, flip-inline, flip-block flip-inline;
}

/* Or define custom fallback positions */
@position-try --above {
  bottom: anchor(top);
  top: auto;
  left: anchor(center);
  translate: -50% 0;
  margin-bottom: 8px;
  margin-top: 0;
}

@position-try --right-side {
  left: anchor(right);
  top: anchor(center);
  translate: 0 -50%;
  margin-left: 8px;
  margin-top: 0;
}

.smart-tooltip {
  position-try-fallbacks: --above, --right-side;
}

Built-in Flip Keywords

  • flip-block — Flips in the block direction (top/bottom in horizontal writing modes).
  • flip-inline — Flips in the inline direction (left/right).
  • flip-block flip-inline — Flips in both directions (diagonally opposite).

6. Popover API

The Popover API is a built-in HTML feature that provides dismissible overlay elements — no JavaScript required for basic show/hide behavior. Combined with CSS @starting-style, you get animated entry and exit transitions.

Core Attributes

HTML

<!-- The trigger button -->
<button popovertarget="my-popover">Open Menu</button>

<!-- The popover element -->
<div id="my-popover" popover>
  <h3>Menu</h3>
  <nav>
    <a href="#">Profile</a>
    <a href="#">Settings</a>
    <a href="#">Logout</a>
  </nav>
</div>

Popover Types

  • popover (or popover="auto") — Light-dismiss: clicking outside or pressing Escape closes it. Only one auto popover can be open at a time.
  • popover="manual" — Must be explicitly closed. Multiple manual popovers can coexist.

Styling with :popover-open and @starting-style

CSS

/* Base popover styles (hidden state) */
[popover] {
  padding: 1.5rem;
  border: none;
  border-radius: 12px;
  box-shadow: 0 20px 60px rgba(0, 0, 0, 0.3);
  background: white;

  /* Enable transitions for open/close */
  opacity: 0;
  transform: translateY(10px) scale(0.95);
  transition:
    opacity 0.3s ease,
    transform 0.3s ease,
    overlay 0.3s ease allow-discrete,
    display 0.3s ease allow-discrete;
}

/* Open state */
[popover]:popover-open {
  opacity: 1;
  transform: translateY(0) scale(1);
}

/* Entry animation starting point */
@starting-style {
  [popover]:popover-open {
    opacity: 0;
    transform: translateY(10px) scale(0.95);
  }
}

7. Combining All Three

The real power emerges when you combine View Transitions, Anchor Positioning, and the Popover API into a cohesive navigation system. Here is a complete example: a navigation bar with anchor-positioned dropdown menus, a popover mobile menu, and view-transition-enabled page morphs.

HTML + CSS Architecture

<!-- Navigation with all three features -->
<nav class="mega-nav">
  <!-- Logo morphs between pages via view-transition -->
  <a href="/" class="mega-logo" style="view-transition-name: site-logo">
    Brand
  </a>

  <!-- Desktop links with anchor-positioned dropdowns -->
  <ul class="mega-links">
    <li>
      <button class="mega-link" style="anchor-name: --products-anchor">
        Products
      </button>
      <div class="mega-dropdown"
           style="position-anchor: --products-anchor;
                  top: anchor(bottom);
                  left: anchor(left);
                  position-try-fallbacks: flip-block;">
        <!-- Dropdown content -->
      </div>
    </li>
  </ul>

  <!-- Mobile: popover hamburger menu -->
  <button popovertarget="mobile-nav" class="mega-hamburger">
    ☰
  </button>
  <div id="mobile-nav" popover class="mega-mobile-menu">
    <!-- Full mobile navigation -->
  </div>
</nav>

<style>
  /* Enable cross-page transitions */
  @view-transition { navigation: auto; }

  /* Anchor dropdown positioning */
  .mega-dropdown {
    position: fixed;
    margin-top: 4px;
    opacity: 0;
    pointer-events: none;
    transition: opacity 0.2s;
  }

  .mega-link:hover + .mega-dropdown,
  .mega-link:focus + .mega-dropdown,
  .mega-dropdown:hover {
    opacity: 1;
    pointer-events: auto;
  }

  /* Popover mobile menu with animation */
  .mega-mobile-menu {
    inset: 0;
    transform: translateX(100%);
    transition: transform 0.35s ease, display 0.35s allow-discrete;
  }

  .mega-mobile-menu:popover-open {
    transform: translateX(0);
  }

  @starting-style {
    .mega-mobile-menu:popover-open {
      transform: translateX(100%);
    }
  }
</style>

Requirements

  • Create at least 4 trigger elements: a button, a link, an icon, and an inline code snippet.

Challenge: Multi-Page Portfolio Mockup

Build a multi-page portfolio mockup with view transitions between sections, anchored tooltips for project details, and a popover contact form.

Requirements

  • View Transitions: Use @view-transition { navigation: auto; } and assign view-transition-name to the header, project cards, and page title so they morph between pages.
  • Anchor Tooltips: Each project card has an info icon with an anchor-positioned tooltip showing technology stack, completion date, and links.
  • Popover Contact Form: A "Contact Me" button opens a popover with a styled form. Animate entry with @starting-style.
  • Mobile Responsive: Stack layouts on small screens, convert nav to a popover hamburger menu.
  • At least 3 pages: Home, Projects, and a Project Detail page.
  • Custom transition animations: Use ::view-transition-old and ::view-transition-new for at least one element with a non-default animation.

Hints

  • Give each project card a unique view-transition-name like project-1, project-2, etc.
  • On the detail page, the hero image should share the same view-transition-name as the card thumbnail for a morph effect.
  • Use position-try-fallbacks on tooltips so they work on cards near the page edges.
  • For the popover form, use popover="manual" so users do not accidentally dismiss it while filling out fields.
