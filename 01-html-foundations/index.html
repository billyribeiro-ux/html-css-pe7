The Building Blocks

Master the fundamental HTML elements that form every web page on the internet.

1. Document Structure

Every HTML document follows a specific structure that browsers rely on to correctly interpret and render your content. Think of it as the skeleton of a building: invisible to visitors, but absolutely essential for everything else to stand properly. Without a correct document structure, browsers enter "quirks mode" and may render your page unpredictably.

The structure begins with a declaration that tells the browser which version of HTML you are using. Then comes the root element that wraps everything, followed by two main sections: the <head> for metadata and the <body> for visible content. Every tag you write lives inside one of these two containers.

Metadata in the <head> includes the character encoding, viewport settings for mobile devices, the page title (shown in browser tabs), links to stylesheets, and other machine-readable information. None of this content is displayed on the page itself, but it profoundly affects how the page behaves.

Understanding this anatomy is not just academic. Search engines read your <title> and meta tags. Screen readers depend on proper language attributes. Mobile browsers need the viewport meta tag to display your page at the correct scale. Getting the foundation right means everything built on top works correctly.

Anatomy of an HTML Document

<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <meta name="description" content="A brief description of your page">
  <title>My First Web Page</title>
  <link rel="stylesheet" href="styles.css">
</head>
<body>
  <h1>Hello, World!</h1>
  <p>This is my first web page.</p>
</body>
</html>

Why Each Part Matters

  • <!DOCTYPE html> — Tells the browser to use modern standards mode. Without it, browsers fall back to "quirks mode" which emulates bugs from the 1990s.
  • <html lang="en"> — The root element. The lang attribute helps screen readers pronounce text correctly and enables browser translation features.
  • <meta charset="UTF-8"> — Ensures characters from all languages (including emojis) display correctly. Always place this first in the head.
  • <meta name="viewport"> — Without this, mobile browsers render the page at desktop width and then shrink it down, making text unreadable.
  • <title> — Appears in browser tabs, bookmarks, and search engine results. It is one of the most important SEO elements on any page.

2. Semantic Elements

Semantic HTML means using elements that describe the meaning of your content, not just its appearance. Before HTML5, developers used generic <div> tags for everything and relied on class names like "header" or "sidebar" to convey purpose. Now we have dedicated elements that communicate structure to browsers, screen readers, and search engines.

Using semantic elements is not optional best practice — it is how HTML is designed to be written. Screen readers use these landmarks to let users jump between sections. Search engines use them to understand page hierarchy. Other developers reading your code can instantly understand the layout without deciphering class names.

The key semantic elements are: <header> for introductory content, <nav> for navigation links, <main> for the primary content (only one per page), <article> for self-contained compositions, <section> for thematic groupings, <aside> for tangentially related content, and <footer> for closing information.

A page can have multiple <header> and <footer> elements (one for the page, others inside articles or sections), but there should only be one <main>. The <article> element should make sense on its own if extracted from the page — think blog posts, news stories, or product cards.

Proper Semantic Structure

<body>
  <header>
    <h1>My Website</h1>
    <nav>
      <a href="/">Home</a>
      <a href="/about">About</a>
      <a href="/contact">Contact</a>
    </nav>
  </header>

  <main>
    <article>
      <h2>Article Title</h2>
      <p>Article content...</p>
    </article>

    <section>
      <h2>Related Topics</h2>
      <p>Section content...</p>
    </section>
  </main>

  <aside>
    <h3>Sidebar</h3>
    <p>Related links, ads, etc.</p>
  </aside>

  <footer>
    <p>&copy; 2026 My Website</p>
  </footer>
</body>

Why Semantics Matter

A <div> tells the browser nothing about its content. A <nav> tells screen readers "this is a navigation region — skip it if you want to jump to the main content." Semantic HTML is the foundation of accessible web development. It is also a ranking factor for search engines, which use semantic structure to understand page content and display rich search results.

3. Text Content

Text is the backbone of the web. HTML provides a rich set of elements for structuring text content, from headings that create document outlines to paragraphs, emphasis, and quotations. Using the right element for the right purpose ensures your content is accessible, well-structured, and meaningful.

Headings (<h1> through <h6>) create a hierarchical outline of your document. Think of them like the outline of a book: <h1> is the book title, <h2> is a chapter title, <h3> is a section within a chapter, and so on. Never skip heading levels (going from h1 to h3 without an h2) as this breaks the document outline for assistive technologies.

For inline text semantics, <em> represents stress emphasis (the browser defaults to italic), while <strong> represents strong importance (the browser defaults to bold). These are different from <i> and <b>, which are purely visual. Screen readers change their tone of voice for <em> and <strong> but not for <i> and <b>.

The <blockquote> element is used for extended quotations from another source. It is a block-level element that typically gets indented by browsers. You can include a <cite> element to attribute the source of the quote.

Why Correct Text Markup Matters

Screen readers announce headings and let users navigate by heading level. Using <strong> instead of CSS font-weight: bold conveys meaning to assistive technologies. Proper text structure also helps search engines understand the key topics on your page and their relative importance.

4. Lists

Lists are one of the most commonly used HTML structures. They appear everywhere: navigation menus, feature lists, step-by-step instructions, recipe ingredients, and more. HTML provides three types of lists, each with a specific semantic purpose.

Unordered lists (<ul>) are for items where the order does not matter — like a shopping list or a set of features. Ordered lists (<ol>) are for items where sequence is important — like instructions, rankings, or steps. Description lists (<dl>) are for name-value pairs — like a glossary, FAQ, or metadata display.

Lists can be nested inside each other to create hierarchical structures. Navigation menus with submenus are commonly built with nested unordered lists. Screen readers announce the type and length of lists, helping users understand the structure of your content.

5. Links & Images

Links and images are what transformed documents into the interconnected, visual web we know today. The anchor element (<a>) creates hyperlinks that connect pages together, while the image element (<img>) embeds visual content. Both require careful attention to accessibility.

The href attribute on links can point to other pages (relative or absolute URLs), specific sections on the same page (using #id), email addresses (mailto:), or phone numbers (tel:). The target="_blank" attribute opens links in a new tab, but should be used sparingly and always with rel="noopener noreferrer" for security.

Images must always include an alt attribute that describes the image for users who cannot see it. If the image is purely decorative, use an empty alt="" so screen readers skip it. The loading="lazy" attribute defers loading images until they are near the viewport, improving page performance significantly on image-heavy pages.

Link text should be descriptive and make sense out of context. Avoid generic text like "click here" or "read more" — screen reader users often navigate by listing all links on a page, and "click here" repeated five times is useless. Instead, write "Read the full article about CSS Grid" or "Download the project files."

Links & Images

<!-- External link opening in new tab -->
<a href="https://example.com" target="_blank" rel="noopener noreferrer">
  Visit Example.com
</a>

<!-- Internal page link -->
<a href="/about.html">About Us</a>

<!-- Jump to section on same page -->
<a href="#contact">Skip to Contact Section</a>

<!-- Image with alt text -->
<img src="photo.jpg" alt="A golden retriever playing in the park" loading="lazy">

<!-- Decorative image -->
<img src="divider.svg" alt="" role="presentation">

Why Accessibility Matters Here

Approximately 15% of the world's population has some form of disability. The alt attribute on images is not optional — it is required by the HTML specification and by accessibility laws in many countries. Descriptive link text helps all users understand where a link will take them, and it is essential for screen reader users who may navigate a page by tabbing through links.

6. Tables

HTML tables are designed for displaying tabular data — information that is logically organized into rows and columns. They should never be used for page layout (that is what CSS Flexbox and Grid are for). When used correctly, tables are powerful tools for presenting data clearly and accessibly.

A well-structured table uses <thead> for the header row, <tbody> for the data rows, and optionally <tfoot> for summary rows. The <th> element marks header cells and has a scope attribute ("col" or "row") that tells screen readers which data cells the header describes.

The <caption> element provides a title for the table and is essential for accessibility. Think of it as the table's alt text — it tells screen reader users what data the table contains before they start navigating it.

Tables can be styled extensively with CSS. Alternating row colors (zebra striping), hover effects, and responsive behavior can all be achieved without changing the HTML. The key is to keep the HTML semantic and let CSS handle the presentation.

7. Forms

Forms are the primary way users interact with web pages beyond clicking links. Every login screen, search bar, checkout process, and contact page relies on HTML forms. Understanding form elements and their attributes is essential for building usable, accessible web applications.

The <form> element wraps all form controls. It has an action attribute (where data is sent) and a method attribute (GET for retrieving data, POST for submitting data). Inside, you use <input> elements with different type attributes for different kinds of data.

Every form control must have a <label> element associated with it, either by wrapping the control or using the for attribute that matches the control's id. Labels are essential for accessibility — they tell screen reader users what each field is for, and clicking a label focuses the associated input, increasing the clickable area.

HTML5 introduced many new input types: email, url, tel, number, date, color, range, and more. These provide built-in validation, appropriate mobile keyboards, and native date/color pickers without needing JavaScript. Always use the most specific input type for the data you are collecting.

The <select> element creates dropdown menus, <textarea> provides multi-line text input, and <fieldset> with <legend> groups related controls together (essential for radio buttons and checkboxes).

Why Labels and Input Types Matter

Using <label> elements is not just good practice — it is a requirement for accessible forms. Without labels, screen reader users have no idea what a text field is asking for. Correct type attributes (like email or tel) trigger appropriate virtual keyboards on mobile devices and provide free built-in validation, reducing the amount of JavaScript you need to write.

Exercise: Build a Personal Profile Page

Using all the semantic elements you have learned, build a personal profile page that includes:

  • A <header> with your name as an <h1> and a <nav> linking to sections on the page.
  • A <main> containing an <article> with a short bio using paragraphs, emphasis, and a blockquote of your favorite quote.
  • A <section> listing your skills using an unordered list.
  • A <section> with a table showing your education or work history.
  • An <aside> with links to your social profiles.
  • A <footer> with a contact form (name, email, message, submit button).

Ensure every image has meaningful alt text, every form control has a label, and heading levels follow the correct hierarchy.

Challenge: Create a Recipe Page

Build a complete recipe page for your favorite dish. It must include:

  • A descriptive <title> and proper document structure with all required meta tags.
  • A page <header> with the recipe name as <h1> and a short description paragraph.
  • An ingredients section using an unordered list.
  • A preparation steps section using an ordered list.
  • A nutrition facts section using a data table with proper <thead>, <tbody>, <th> with scope, and a <caption>.
  • A review form with: text input for reviewer name, email input, a 1-5 star rating (radio buttons), a textarea for the review, and a submit button. All controls must have labels.

Bonus: Add a description list (<dl>) for metadata like prep time, cook time, servings, and difficulty.
