1. CSS Transitions

CSS transitions are the simplest way to add motion to your interfaces. A transition smoothly interpolates a CSS property from one value to another over a specified duration, triggered by a state change such as :hover, :focus, or a class toggle. Instead of values snapping instantly, they animate fluidly, giving users visual feedback that something is happening.

Transitions are controlled by four sub-properties. transition-property specifies which CSS property (or properties) to animate. transition-duration sets how long the animation takes, typically in milliseconds or seconds. transition-timing-function controls the acceleration curve — whether the animation starts fast and slows down, moves at a constant speed, or follows a custom curve. transition-delay adds a pause before the transition begins, which is useful for staggering multiple animations or preventing accidental triggers on quick mouse movements.

The shorthand transition property combines all four values in a single declaration. You can also transition multiple properties by comma-separating them. Using transition: all is convenient but can cause performance issues because the browser will attempt to transition every changed property, including ones you might not intend to animate. Best practice is to list specific properties explicitly.

Why Transitions Matter: Without transitions, state changes are jarring — a button color snapping from blue to dark blue on hover feels broken. Transitions make your UI feel responsive, polished, and intentional. They provide continuity, helping users track what changed and why. A well-chosen 200ms transition can be the difference between an interface feeling cheap and feeling premium. 
/* Individual transition properties */
.button {
  background-color: #6366f1;
  color: white;
  padding: 12px 24px;
  border-radius: 8px;
  border: 2px solid transparent;

  transition-property: background-color, transform, box-shadow;
  transition-duration: 200ms;
  transition-timing-function: ease;
  transition-delay: 0s;
}

.button:hover {
  background-color: #4f46e5;
  transform: translateY(-2px);
  box-shadow: 0 4px 12px rgba(99, 102, 241, 0.4);
}

/* Shorthand - property duration timing delay */
.button-shorthand {
  transition: background-color 200ms ease,
              transform 150ms ease-out,
              box-shadow 300ms ease;
}

/* Multiple properties with different timings */
.card {
  transition: transform 200ms ease,
              box-shadow 300ms ease 50ms,
              border-color 150ms ease;
}

2. Timing Functions

The timing function (also called an easing function) defines the rate of change over the duration of a transition or animation. It determines whether motion starts slowly and accelerates, moves at a constant speed, or decelerates at the end. Choosing the right timing function is critical — it is often the difference between motion that feels natural and motion that feels robotic or jarring.

CSS provides several built-in keyword timing functions. ease (the default) starts slowly, accelerates in the middle, and decelerates at the end — it works well for most UI interactions. linear moves at a constant speed with no acceleration, which can feel mechanical but is perfect for things like progress bars or continuous rotations. ease-in starts slowly and accelerates, making it good for elements exiting the screen. ease-out starts fast and decelerates, ideal for elements entering the screen. ease-in-out combines both, creating a symmetrical acceleration curve.

For precise control, cubic-bezier(x1, y1, x2, y2) lets you define a custom curve using two control points. The curve maps time (x-axis) to progress (y-axis). Values outside the 0–1 range on the y-axis create overshoot effects, like a bouncy spring. Tools like cubic-bezier.com help you visualize and craft custom curves.

CSS now also supports the linear() function (not to be confused with the linear keyword). This powerful new addition lets you define arbitrary easing curves by specifying a series of output values at specific progress points. The browser linearly interpolates between these points, enabling complex curves like bounce, elastic, or spring effects that were previously impossible without JavaScript.

Why Timing Functions Matter: In the physical world, nothing moves at a constant speed. Objects accelerate due to force and decelerate due to friction. When UI elements move with proper easing, they feel like they have weight and substance. The wrong timing function makes motion feel "off" in a way users sense even if they cannot articulate it. 
/* Built-in timing functions */
.ease       { transition-timing-function: ease; }
.linear     { transition-timing-function: linear; }
.ease-in    { transition-timing-function: ease-in; }
.ease-out   { transition-timing-function: ease-out; }
.ease-in-out { transition-timing-function: ease-in-out; }

/* Custom cubic-bezier - a snappy, slightly bouncy curve */
.snappy {
  transition-timing-function: cubic-bezier(0.34, 1.56, 0.64, 1);
}

/* Overshoot effect */
.overshoot {
  transition-timing-function: cubic-bezier(0.68, -0.55, 0.27, 1.55);
}

/* New linear() function for complex curves */
/* A bounce effect */
.bounce {
  transition-timing-function: linear(
    0, 0.004, 0.016, 0.035, 0.063, 0.098, 0.141, 0.191,
    0.25, 0.316, 0.391, 0.473, 0.563, 0.66, 0.766, 0.879,
    1, 0.955, 0.922, 0.9, 0.891, 0.9, 0.922, 0.955,
    1, 0.984, 0.975, 0.975, 0.984, 1
  );
}

/* Spring effect with linear() */
.spring {
  transition-timing-function: linear(
    0, 0.009, 0.035, 0.078, 0.141, 0.223, 0.326, 0.45,
    0.594, 0.757, 0.938, 1.1, 1.2, 1.2, 1.15, 1.08,
    1.03, 1, 0.985, 0.98, 0.985, 1
  );
}

3. @keyframes

While transitions animate between two states (a starting value and an ending value), @keyframes let you define animations with any number of intermediate steps. A keyframe animation can loop indefinitely, reverse direction, pause and resume, and control timing at each step independently. This makes keyframes far more powerful than transitions for complex, multi-step animations.

You define a keyframe animation using the @keyframes rule followed by a name. Inside the block, you specify keyframe selectors that represent points along the animation timeline. The simplest form uses from (equivalent to 0%) and to (equivalent to 100%). For multi-step animations, you use percentage values like 0%, 25%, 50%, 75%, 100%. The browser interpolates between each keyframe according to the timing function.

A single keyframe block can animate multiple properties simultaneously. You can also assign the same styles to multiple keyframe selectors by comma-separating them (e.g., 0%, 100%). This is useful for creating animations that return to their starting state, like a pulse or a bounce.

Why @keyframes Matter: Transitions are limited to two states and require a trigger. Keyframe animations can run automatically on page load, loop forever, go through multiple stages, and create effects that would be impossible with transitions alone — loading spinners, attention-grabbing pulses, skeleton screens, and complex choreographed sequences. 
/* Simple from/to animation */
@keyframes fadeIn {
  from {
    opacity: 0;
    transform: translateY(20px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

/* Multi-step animation with percentages */
@keyframes pulse {
  0% {
    transform: scale(1);
    box-shadow: 0 0 0 0 rgba(99, 102, 241, 0.7);
  }
  50% {
    transform: scale(1.05);
    box-shadow: 0 0 0 10px rgba(99, 102, 241, 0);
  }
  100% {
    transform: scale(1);
    box-shadow: 0 0 0 0 rgba(99, 102, 241, 0);
  }
}

/* Loading spinner with rotation */
@keyframes spin {
  from { transform: rotate(0deg); }
  to   { transform: rotate(360deg); }
}

/* Complex bounce */
@keyframes bounce {
  0%, 100% { transform: translateY(0); }
  20%      { transform: translateY(-30px); }
  40%      { transform: translateY(-15px); }
  60%      { transform: translateY(-5px); }
  80%      { transform: translateY(-2px); }
}

4. Animation Properties

Once you have defined a @keyframes rule, you apply it to an element using the animation property (or its individual sub-properties). There are eight animation sub-properties, each controlling a different aspect of how the animation plays.

animation-name references the @keyframes rule to use. animation-duration sets how long one cycle takes. animation-timing-function controls the easing curve, just like transitions. animation-delay postpones the start — negative values cause the animation to begin partway through its cycle, which is great for staggered effects.

animation-iteration-count sets how many times the animation repeats. Use a number for a fixed count or infinite for continuous animation. animation-direction controls playback direction: normal plays forward, reverse plays backward, alternate ping-pongs between forward and backward, and alternate-reverse starts backward then alternates. animation-fill-mode determines what styles apply before the animation starts and after it ends — forwards retains the final keyframe values, backwards applies the first keyframe during the delay, and both does both. animation-play-state lets you pause and resume with paused and running.

Why Understanding All Animation Properties Matters: Most developers learn animation-name and animation-duration but overlook the rest. Mastering fill-mode prevents the jarring snap-back when an animation ends. Understanding negative delays enables staggered reveals. play-state lets you pause animations for accessibility (prefers-reduced-motion) without removing them entirely. 
/* All animation sub-properties */
.element {
  animation-name: bounce;
  animation-duration: 1s;
  animation-timing-function: ease-in-out;
  animation-delay: 0s;
  animation-iteration-count: infinite;
  animation-direction: alternate;
  animation-fill-mode: both;
  animation-play-state: running;
}

/* Shorthand: name duration timing delay count direction fill play */
.element-short {
  animation: bounce 1s ease-in-out 0s infinite alternate both running;
}

/* Practical: staggered list items with negative delays */
.item:nth-child(1) { animation: fadeIn 0.5s ease both; }
.item:nth-child(2) { animation: fadeIn 0.5s ease 0.1s both; }
.item:nth-child(3) { animation: fadeIn 0.5s ease 0.2s both; }
.item:nth-child(4) { animation: fadeIn 0.5s ease 0.3s both; }

/* Pause animation for reduced-motion preference */
@media (prefers-reduced-motion: reduce) {
  .element {
    animation-play-state: paused;
    animation-delay: -1s; /* Jump to final state */
  }
}

5. @starting-style

@starting-style is a game-changing CSS feature that solves a long-standing problem: how do you animate an element's initial appearance when it first enters the DOM or first becomes visible? Previously, elements would simply appear with their final styles — there was no "before" state for the browser to transition from. You had to use JavaScript to add classes after a requestAnimationFrame, which was hacky and unreliable.

@starting-style lets you define the styles an element should start with before its normal styles take effect. The browser applies the @starting-style values first, then transitions to the element's actual styles. This creates smooth entrance animations purely in CSS, without any JavaScript timing tricks.

You can use @starting-style either nested inside a rule or as a standalone block. The nested form is more readable and clearly associates the starting styles with their element. The browser uses these starting styles as the "from" state whenever the element first renders or transitions from display: none to visible.

Why @starting-style Changes Everything: Before this feature, entrance animations required JavaScript. You had to render the element, wait a frame, then add an "active" class to trigger the transition. This was fragile, created layout thrashing, and added complexity. @starting-style makes entrance animations a pure CSS concern, which is where they belong. 
/* Before @starting-style: Required JavaScript */
/* JS: element.classList.add('visible'); after rAF */
.card {
  opacity: 0;
  transform: translateY(20px);
  transition: opacity 0.4s ease, transform 0.4s ease;
}
.card.visible {
  opacity: 1;
  transform: translateY(0);
}

/* After: Pure CSS with @starting-style */
.card {
  opacity: 1;
  transform: translateY(0);
  transition: opacity 0.4s ease, transform 0.4s ease;

  @starting-style {
    opacity: 0;
    transform: translateY(20px);
  }
}

/* Standalone syntax (equivalent) */
@starting-style {
  .card {
    opacity: 0;
    transform: translateY(20px);
  }
}

6. interpolate-size

One of the most requested CSS features for years has been the ability to transition height: auto. When you want to smoothly expand or collapse an element — like an accordion panel, a dropdown menu, or a details/summary disclosure — you need to transition between height: 0 and the element's natural content height. But the browser cannot interpolate between 0 and auto because auto is a keyword, not a numeric value.

The interpolate-size property changes this. When set to allow-keywords, it tells the browser that keyword sizing values like auto, min-content, max-content, and fit-content should be treated as interpolatable for the purpose of transitions and animations. This means you can finally transition height: 0 to height: auto and get a smooth animation.

The best practice is to set interpolate-size: allow-keywords on :root so it applies globally. Since it inherits, every element in your document will gain this capability. This is a progressive enhancement — browsers that do not support it will simply show the content without animation, which is an acceptable fallback.

Why This Is Huge: Developers have been using JavaScript's scrollHeight, max-height hacks (setting an absurdly large max-height), or CSS Grid tricks (grid-template-rows: 0fr to 1fr) to work around this limitation for over a decade. interpolate-size eliminates all of those workarounds with a single line of CSS. Accordions, FAQs, expandable sections, and disclosure widgets become trivially simple. 
/* Enable globally - set once, works everywhere */
:root {
  interpolate-size: allow-keywords;
}

/* Now height: auto transitions just work! */
.accordion-panel {
  height: 0;
  overflow: hidden;
  transition: height 0.35s ease;
}

.accordion-item.open .accordion-panel {
  height: auto;
}

/* Works with width too */
.expandable-sidebar {
  width: 0;
  overflow: hidden;
  transition: width 0.3s ease;
}

.expandable-sidebar.open {
  width: auto;
}

/* Also works with min-content, max-content, fit-content */
.flexible-box {
  width: fit-content;
  transition: width 0.3s ease;
}

.flexible-box.expanded {
  width: auto;
}

interpolate-size is a CSS property that enables transitions and animations on keyword sizing values like auto, min-content, max-content, and fit-content. It solves the decade-old problem of animating height: auto.

Add interpolate-size: allow-keywords to your :root selector. Then simply transition between height: 0 and height: auto as you normally would. The browser handles the interpolation automatically. No JavaScript needed, no max-height hacks, no grid tricks.

As of 2025, interpolate-size is supported in Chrome/Edge 129+ and Safari 17.5+. Firefox support is in progress. Because it is a progressive enhancement, unsupported browsers simply show content without animation — nothing breaks.

7. Display None Animations

Historically, you could not animate or transition the display property at all. Toggling between display: none and display: block was an instantaneous switch — the element was either fully removed from the layout or fully present, with no in-between state. This forced developers to use visibility, opacity, pointer-events, and position: absolute hacks to simulate hiding while keeping elements in the DOM for animation purposes.

The transition-behavior property with the value allow-discrete changes this. It tells the browser that discrete properties like display and overlay should participate in transitions. Combined with @starting-style, you can now animate an element appearing (from display: none to visible) and disappearing (back to display: none) with smooth opacity, transform, or any other transitions.

The key insight is that when an element transitions to display: none, the browser keeps it visible long enough for exit transitions to complete. When transitioning from display: none, @starting-style provides the initial values to transition from. This two-part system gives you complete control over entrance and exit animations for elements that are truly removed from layout.

Why This Matters: Modals, popovers, dropdown menus, tooltips, and toast notifications all need to appear and disappear. Before transition-behavior: allow-discrete, you had to keep hidden elements in the DOM (wasting memory, creating accessibility issues) or use JavaScript animation libraries. Now the browser handles the entire lifecycle natively. 
/* The complete pattern for display none animations */
.modal {
  /* Final visible state */
  opacity: 1;
  transform: scale(1);
  display: block;

  /* Transition all properties including display */
  transition: opacity 0.3s ease,
              transform 0.3s ease,
              display 0.3s ease allow-discrete;

  /* Starting state when appearing */
  @starting-style {
    opacity: 0;
    transform: scale(0.95);
  }
}

/* Hidden state - exit animation plays, then display goes to none */
.modal.hidden {
  opacity: 0;
  transform: scale(0.95);
  display: none;
}

/* You can also use transition-behavior as a separate property */
.tooltip {
  transition-property: opacity, transform, display;
  transition-duration: 0.2s;
  transition-behavior: allow-discrete;
}

8. Practical Patterns

Theory is valuable, but the real power of CSS animations comes alive in practical, production-ready patterns. This section demonstrates four common UI patterns that combine the techniques covered in this module: toast notifications, card hover lifts, skeleton loading screens, and staggered list reveals. Each pattern is production-quality and can be copied directly into your projects.

These patterns share a common philosophy: motion should serve a purpose. Toast notifications need to grab attention and then disappear. Card hover lifts provide tactile feedback. Skeleton screens reduce perceived loading time by showing movement where content will appear. Staggered reveals create a sense of choreography that guides the user's eye through content in a deliberate order.

Why Practical Patterns: Knowing the syntax is not enough. Understanding when and how to apply each technique separates beginners from professionals. These patterns also demonstrate how multiple animation techniques compose together — a toast notification uses keyframes, transitions, fill-mode, and timing functions all at once. 
/* Pattern: Card Hover Lift */
.card {
  transition: transform 0.2s ease, box-shadow 0.2s ease;
}
.card:hover {
  transform: translateY(-4px);
  box-shadow: 0 12px 24px rgba(0, 0, 0, 0.15);
}

/* Pattern: Skeleton Loading */
@keyframes shimmer {
  0%   { background-position: -200% 0; }
  100% { background-position: 200% 0; }
}
.skeleton {
  background: linear-gradient(90deg, #e2e8f0 25%, #f1f5f9 50%, #e2e8f0 75%);
  background-size: 200% 100%;
  animation: shimmer 1.5s ease-in-out infinite;
  border-radius: 4px;
}

/* Pattern: Staggered List Reveal */
.list-item {
  animation: fadeSlideIn 0.4s ease both;
}
.list-item:nth-child(1) { animation-delay: 0s; }
.list-item:nth-child(2) { animation-delay: 0.08s; }
.list-item:nth-child(3) { animation-delay: 0.16s; }
.list-item:nth-child(4) { animation-delay: 0.24s; }
.list-item:nth-child(5) { animation-delay: 0.32s; }

Challenge: Multi-Step Onboarding Flow

Build a multi-step onboarding flow where each step transitions in with staggered entrance animations and the container smoothly adjusts its height as content changes. This challenge combines @starting-style, interpolate-size, staggered animation-delay, and transition-behavior: allow-discrete.

Requirements:

  1. Create a 3-step onboarding wizard (Welcome, Profile Setup, Confirmation).
  2. Each step's content elements (heading, text, inputs, buttons) animate in with staggered delays using @starting-style or keyframe animations.
  3. The container height transitions smoothly between steps using interpolate-size: allow-keywords.
  4. Outgoing step content fades out before the incoming step fades in. Use transition-behavior: allow-discrete to handle the display toggle.
  5. Add a progress bar at the top that smoothly fills between steps using a CSS transition.
  6. Include step indicator dots that animate their active state with a scale + color transition.

Bonus:

  • Add directional awareness: content slides left when going forward and slides right when going back.
  • Use the linear() timing function to create a spring-like bounce when elements appear.
  • Implement a confetti animation on the final confirmation step using multiple @keyframes with randomized delays.
/* Challenge starter structure */
.onboarding {
  interpolate-size: allow-keywords;
  /* Container that smoothly adjusts height */
}

.onboarding-step {
  display: none;
  transition: opacity 0.3s ease,
              transform 0.3s ease,
              display 0.3s ease allow-discrete;

  @starting-style {
    opacity: 0;
    transform: translateX(30px);
  }
}

.onboarding-step.active {
  display: block;
  opacity: 1;
  transform: translateX(0);
}

/* Stagger children within each step */
.onboarding-step.active > * {

.onboarding-step.active > *:nth-child(1) { animation-delay: 0.05s; }
.onboarding-step.active > *:nth-child(2) { animation-delay: 0.1s; }
